# 老游戏启动器 GUI 规范

## 定位

一句话：**像街机 / 机车仪表盘，不像 SaaS 后台**。

- 读者是拿到绿色修复包的玩家，不是开发者：一屏看懂「选什么、按什么键、出问题找谁」。
- 整屏只允许一个视觉记忆点 = **右栏的键帽操作表**（把 W/A/S/D 画成真实键帽形状）。
  其余部分克制、等宽、安静。卡片、圆角、阴影都是结构手段，不是装饰。
- 不做：黑底 + 单一荧光色、每块内容一张同样的圆角卡 + 灰阴影、全大写小标题、
  标题上方再叠一行 eyebrow 标签、装饰性动画。

## 风格样张（10 方向）

本技能自带一套可浏览的 HTML 风格样张，统一使用同一套三栏启动器内容和占位文案，用于先选风格、再做 WinForms 实现。样张使用通用内容（「游戏启动器 / YunGame Launcher」），不绑定任何具体游戏：

- 总览：`design-demos/index.html`
- 单看一个方向：`design-demos/index.html?style=leather`（`style` 取下表 id）
- 离线单文件：`design-demos/launcher-styles.html`
- 预览拼图：`design-demos/preview-contact.png`

这些样张是**风格探索**。**2026-11-03 用户定案：GUI 启动器统一按 05 拟物皮革 交付**（配色/材质见「设计令牌」）；
但 WinForms/GDI+、零图片、≤1MB、可读性底线和平台托管契约仍是硬约束。
已经交付出去的中国红 exe 不返工，新做的和重做的都走皮革。

## 硬约束（违反就是错）

1. **只用 .NET Framework 4.x + WinForms + System.Drawing**，系统自带
   `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` 单文件编译。
   不建 `.csproj`、不用 `.resx`、不引第三方 DLL（WinForms 是框架自带的，不算）。
2. **零图片、零内嵌字体、零图标资源文件**（唯一例外：统一启动器图标，仓库资源 `assets\ico.ico`，
   构建时嵌入 exe；`src\` 和游戏目录不放 ico）。键帽、卡片、按钮、状态点全部 GDI+ 现画。
   需要「图标」时用文字 + 形状（`↑` `Alt` `Shift` 就是键帽里的文字）。
3. **体积上限：game_starter.exe ≤ 1 MB**（2026-11-04 用户放宽，早期 60 KB 经验值作废：
   通用键帽库等标准件进来后硬压会牺牲完整平台支持）。零图片、零内嵌字体、零第三方 DLL
   仍是硬约束，体积只是粗筛，真正挡资源靠 `scripts/check-launcher.ps1` 的禁止文件列表
   （`*.png` / `*.ico` / `*.resx` / `*.Designer.cs` 等）。
   用 `scripts/check-launcher.ps1 -Exe <game_starter.exe> -SrcDir <Games\某游戏\src>` 一次查完。
4. **交付形态：GUI 与控制台是两个平级启动器，选项必须一致**。`game_starter.bat` **不是转发 GUI 的薄包装**：
   它用 `echo` 自己生成菜单（中国红 `color 4f`），菜单项、顺序、默认值与 `game_starter.exe` 完全相同，
   玩家选完由 bat **自己启动游戏**并回传退出码；`/go` 跳过菜单按默认项启动。
   改选项/加模式必须两边一起改，不许分叉；两边都要满足下面的「平台托管契约」。
5. **拟物皮革主题**（仓库 AGENTS 规则 10，2026-11-03 定案）：背景 `#3A2015 → #1C0F0A` 竖直渐变 +
   皮纹斜线 + 四角压暗，卡片 `#5A3421 → #3B2116` 带黄铜缝线，强调金 `#E3C07A`、烫金 `#F0D596`，
   正文米黄 `#F4E3C6`；**不要纯黑底**（最暗是近黑棕，那是皮革阴影不是背景色）。
   控制台 bat 仍是中国红 `color 4f`（cmd 只有 16 色，跟 exe 不统一是已知取舍）。
6. **键位表从 reg 现算，不写死文案**：右栏读当前所选 `road*.reg` 的 `Controls` 字节，
   用游戏内部键码表反查标签。写死的说明一定会和实际键位对不上（踩过坑）。
7. 源文件只放仓库 `Games\<游戏>\src\`，游戏目录只收编译好的 `game_starter.exe` + `launcher.ini`。
8. **统一启动器图标，不用游戏图标**：所有 exe 固定嵌入**仓库资源 `assets\ico.ico`**
   （由构建机的 `D:\ico.ico` 复制入库，SHA-256 `4fb1af64…c495`；换机/换人不用重新摆文件），
   构建时 `csc -win32icon:<仓库>\assets\ico.ico`；运行时用
   `Icon.ExtractAssociatedIcon(Application.ExecutablePath)` 取 exe 自身图标，
   窗口 / 任务栏 / 托盘 / 资源管理器共用。取不到才退回 `SystemIcons.Application` 并写进日志。
   **不要再从游戏 exe 抽图标**，否则任务管理器/平台会把启动器认成游戏进程。
   `assets\ico.ico` 缺失时构建失败并提示，不要静默退回游戏图标，也不要在运行时兜底去找 `D:\ico.ico`
   （交付目录里根本没有那个路径）。
   自绘图标（`Bitmap.GetHicon`）16px 下发糊、还多养一段代码，试过，不值得。
9. **交付启动器名字统一：GUI `game_starter.exe`，控制台菜单版 `game_starter.bat`**
   （备用模式跟着叫 `game_starter-soft.bat` / `game_starter-640.bat`）。
   源码仍叫 `src\Launcher.cs`，改的是**产物名**，不是文件名习惯。
   **旧名 `go.exe` / `go.bat` 作废**：`go.exe` 与 Go 工具链同名，而且平台进程树里一排
   `go` 分不清是哪个游戏；`game_starter` 在任务管理器 / `Get-Process` 里一眼可辨。
   所有游戏同名，靠所在目录区分。
   交付仍然**只一个 exe**：自检补层、按键落地、提权全长在它里面（`/go`、`/keymap N`、
   `/selftest`），不要再有 `keymap.exe` 之类伴生文件；只用框架自带的
   `System.Windows.Forms` / `System.Drawing`，不引第三方 DLL（多一个文件就多一类"缺文件"故障）。
   例外：控制台菜单版 bat 居中用的 `_tools\nircmd\nircmdc.exe` 只服务 bat（`if exist` 保护），
   不参与 exe 的运行。
   改名要连根拔：`csc -out:`、包装 bat 里的 `start "" /wait`、`切键-*.bat`、
   自检工具的进程名（`GetProcessesByName` / `-Proc`）、构建脚本的**旧名清理**——
   游戏目录里同时留 `go.exe`/`go.bat` 和 `game_starter.*` 就是两套入口，玩家必点错。
   删旧名要有签名守卫（内容里确实含 `game_starter` 才删），别顺手删掉用户自己的启动脚本。
10. **窗口永不置顶**：不要 `TopMost=true`，也不要 `SetWindowPos(HWND_TOPMOST)`。
    玩家要 Alt+Tab 出去看别的，置顶会压住一切窗口。（调试脚本置顶过，别学它。）
11. **必须有「打开运行日志」按钮**：界面不解释技术细节，细节全进日志（见「运行日志」一节）。
    不要「打开游戏目录」这类把玩家往文件堆里塞的按钮。
12. **左栏只讲游戏**：来历、玩法，以及底部的「玩不了或报错」（点「打开运行日志」→ 把内容发给我们）。
    **右栏只放操作说明（角色动作 + 菜单）**，可以加一行核心操作提示（如化劲时机）；
    进游戏说明、加载提示、分辨率提示不要放右栏；分辨率/启动说明放中栏，技术说明放日志或仓库文档；
    不写 cnc-ddraw / DXVK / 注册表 / 回滚脚本这类技术说明。操作说明优先来自游戏内设置页面，
    核心提示再从官方手册/社区攻略精简，不自己编。
    **表的看法写在右栏自己头上（一行就够）**；左栏不写翻页提示
    （PageUp / PageDown / 用滚轮滚动这类话都不写，玩家自己会滚），
    也不写和右栏重复的「纯键盘总览」。
    玩家界面一律说人话：不出现 `DXVK` / `dgVoodoo` / `cnc-ddraw` / `Mesa` / 兼容层 / 翻译层 /
    HUD / 注册表 / 亲和性 / 偏移 / `0x...` / DLL 文件名。启动方式必须区分 DX9 / DX11 / GDI 时，
    用玩家能懂的结果标注：`DX11（画质更好）`、`DX9（老机器）`、`GDI（软件画面）`；
    不要写渲染器/管线/API。技术细节只进运行日志和仓库文档。
13. **状态指示全窗口只出现一次**：左下角一个 `● 已就绪` 就够。标题带右上角的角标、
    左栏底部的"兼容层就绪 ddraw.dll"这类第二处状态都算重复，玩家会直接要求删掉。
    出错时才把那一句换成人话 + 下一步（`缺兼容层，先双击 兼容修复.bat`）。
14. 脚本一律用 **`pwsh.exe`（PowerShell 7）** 写和跑，不用 `powershell.exe`
    （5.1 会把无 BOM 的 UTF-8 脚本按 ANSI 读，中文注释直接乱码）。
15. **启动方式用下拉框，但只给两个玩家能懂的结果**：`游戏自动检测（推荐）` / `画面异常时（固定桌面分辨率）`；
    不要写「备份 / 直接启动 / 自动检测（重置）/ config」这类技术说明。默认游戏自动检测；
    画面不对时选固定桌面分辨率，或点「修复分辨率」。
    不单独显示「画面 1920×1080」信息块；中栏标题用 `启动说明`，标题下的说明只写一句
    「游戏会自动检测画面。」，下拉框和启动按钮紧挨着；状态栏默认 `已就绪`。
    **下拉框自己还要有一行用途说明，紧贴框放在它上方，见硬约束 18**
    （不算进上面这一句，也不另拉空白）。
16. **界面文案不写平台已负责的通用提示**：`游戏会自动存档`、`请勿关闭电源` 这类无信息量的话
    不要写；平台有存档备份，会和启动器文案冲突。只有游戏存档机制特殊（如只在线上、需要手动导出）
    才提醒，并写清具体差异。每一句要么是游戏特有信息，要么是玩家下一步动作。
17. **所有按键一律走通用拟物键帽库**（用户定案 2026-11-04）：PC / PS / Switch / Xbox
    四平台一套完整标准件，唯一实现 `templates\Keycaps.cs`，规范 `references/keycaps.md`。
    整份复制进 `Games\<游戏>\src\Keycaps.cs`、build 的 csc 参数加一行、
    构造时调 `Keycaps.Configure` 即可用。**不许在 `Launcher.cs` 里另写 `Keycap` /
    `PsGlyph` / `DrawFaceCircle` 之类临时画法**，不许把多个键塞进一个帽；
    **手柄键也必须画成拟物键帽**（旧「键帽只给真正的键盘键、手柄用普通文字」规定作废）。
    键盘拟物键的样板是 `Games\RoadRash\src\Launcher.cs` 的 `Keycap`。
18. **下拉框上方必须写清「这个下拉框是干嘛的」**（用户定案 2026-11-05，同日再次点名）：
    很多玩家看不懂「启动选项」，以为只是画质开关，闪退了更不知道该动它。
    **位置固定在下拉框的上方面、紧贴框**：「启动选项」标签 → 用途说明 → 下拉框，
    不许挪到框下面、不许并到「启动说明」标题下面、不许省略。标准文案（原句照抄）：
    `本下拉框的作用是：如果有闪退等异常，换另一种模式，再启动游戏试试。`
    前缀「本下拉框的作用是：」不能省，否则玩家不知道这句在说哪个控件；
    后半句意思对即可、允许按游戏换个说法，但**不许写成技术腔**
    （`切换渲染模式` / `请尝试备用配置` 这类不算人话），也不许写成保证词。
    它讲的是「玩家下一步动作」，不算硬约束 16 禁止的空话；和硬约束 15 的
    「启动说明只写一句」也不冲突——标题下那句讲默认怎么跑，这句讲出问题怎么办。
    说明按栏宽折行算高度，标签 / 说明 / 框 / 按钮整体顺移，不重叠、不另拉空白。
    若界面文案走 `launcher.ini`，记得 `CenterNote` 只留标题下那句，另加一个
    `ComboHint` 键，四处（源码默认值 + src / payload / 游戏目录 ini）对齐。
    **只对新做 / 重做的启动器生效，已经交付出去的 exe 不返工**（AGENTS 规则 25）。
19. **说明文字里出现手柄键，就必须给出对应键盘键**（用户定案 2026-11-05）：速查表
    「上排手柄键帽 + 下排金色 PC 键帽」只解决了键位表；**卡片说明、底部提醒、口诀
    这类成段文字里只要写了 `R2` / `L2` / `○` / `OPTIONS` 等手柄键名，玩家用键盘就不知道
    该按哪个**。做法二选一或都用：
    ① 文字里紧跟对应键名（`L2(U) 是道具，R2(O) 才是魔法`、
       `按住再按 □△○✕，键盘 J K L 空格`）；
    ② 这一段本身也按 `CheatRow` 排成「手柄键帽 + 金色 PC 键帽 + 说明」一行一组，
       底部红框提醒尤其推荐这种（战神3 `CheatNotes` 就是样板）。
    **移植器键位表没有对应动作的纯手柄功能**（触摸板 / SHARE / PS 键 / L1+○ 钩索等）
    不能空着一格让人猜，要在说明里写明 `本方案未绑定键盘键` 或 `移植器无对应动作`。
    文案别用长括号包一整句：卡片窄，硬换行会把右括号单独甩到下一行；用分号或短括号。
    **只对新做 / 重做的启动器生效，已经交付出去的 exe 不返工**（AGENTS 规则 25）。
20. **键位表放不下就拆「极简右栏 + 独立普通窗口」，不许把主窗口撑大**（用户定案 2026-11-05）：
    主窗口一律按规范基准 `900×620`、三栏 `252 / 296 / 280`，宽度协调；长表塞不进 280 宽的右栏时，
    不是把窗口撑到 1340×880，而是：
    - 右栏只留**极简常用键**（6 行以内，每行仍是「手柄键帽 + 金色 PC 键帽 + 说明」），
      加一行键帽看法，底部放一个「详细按键」按钮；
    - 按钮打开**独立的普通窗口**（`Show()`，**不是 `ShowDialog()`**）——主窗口照样能点、
      能启动游戏、能关；详细窗口可移动、可关，标题栏写清「<游戏名> · 完整按键速查」；
      **详细窗口必须允许最大化 / 拖边框放大**（用户定案 2026-11-05）：
      `FormBorderStyle = Sizable` + `MaximizeBox = true` + `ResizeRedraw`，绘制全部按
      `ClientSize` 动态算；放大后两列更宽、说明更容易一行，仍要一屏看全。
      **主窗口反过来仍是 `FixedDialog` + `MaximizeBox=false`，不许跟着放大**；
    - **默认两个窗口并排、不遮挡**：打开时把主窗口让位到工作区左侧，详细窗口占右侧全部剩余宽度，
      `StartPosition = Manual` + `OnShown` 校正；关掉详细窗口把主窗口放回原位（启动仍居中）。
      实机量两个窗口矩形，**默认状态下重叠面积必须为 0**；玩家自己点最大化后盖住主窗口
      是他主动要的，不算违规；滚动支持保留作兜底，但默认不该用上；
    - 详细窗口**沿用原来的两列六卡片 + 底部全宽红框结构，不要改成单列长条**；
      **去掉内容区顶部的大标题和说明行**，从第一张卡片直接开始；
      左右做宽、两列行数配平、把冗长说明压短（键位和 PC 对应一个不丢）、收紧行距和卡间距，
      **争取一页看全貌、不用鼠标滚轮**（战神3 实测内容 946 / 视口 953，滚动 0）。
      卡片尾部要留 6px 空白，别让最后一行说明压在缝线上；
      仍**复用主窗口同一套数据、绘制方法和通用键帽库**（战神3 用嵌套 `CheatSheetForm`
      调宿主 `DrawCheatContent`），别另抄一份导致两边键位漂移；主窗口关闭时一起关掉。
    这属于界面内的导航按钮，**不违反「禁止写『完整秘技见某文件』这类指路废话」**——
    那条禁的是把玩家支到外部文件，不是禁开窗口。
    **只对新做 / 重做的启动器生效，已经交付出去的 exe 不返工**（AGENTS 规则 25）。

## 平台托管契约（bat 凭什么被信任，GUI 就得凭什么）

玩家的游戏平台（Playnite 这类）用**启动脚本 + 进程树**监控游戏：脚本崩了、游戏异常退出，
平台要能抓到并报警。bat 之所以好用是因为它天然满足四条，GUI 必须一条不落地复刻：

| # | 平台依赖的性质 | GUI 必须怎么做 |
|---|---|---|
| 1 | 游戏在启动器的**进程树**里 | 用 `Process.Start` + `UseShellExecute=false` 直接起游戏，游戏是 game_starter.exe 的子进程；**不要**用 `shell:"<exe>"`、`explorer.exe`、`cmd /c start` 这类会换父进程的方式 |
| 2 | 启动器活着 = 会话活着 | 游戏运行期间 game_starter.exe 不退出（后台线程 `WaitForExit`），且**主窗口保持可见**（2026-11-12 用户定案：右栏操作说明要一直留着，除非玩家自己点退出）：点「启动游戏」后只改按钮态和状态栏，**不许 Hide / 托盘化**；只有玩家主动关窗（×/退出/Esc）才隐藏到托盘陪跑 |
| 3 | 游戏退出码能回传 | 游戏一退出，game_starter.exe 立刻退出并 `return 游戏退出码`；平台靠 `0xC0000xxx` 这类码判异常。**吞掉退出码 = 崩溃查不到** |
| 4 | 关启动器不杀游戏，且**游戏退出码不能丢** | 关窗 = **隐藏到后台陪跑**（托盘图标双击唤回，图标用 GDI+ 现画，不引图片资源）；游戏退出后 game_starter.exe 才结束并回传游戏码。玩家要是把 game_starter.exe 整个杀掉，游戏仍带着它的父 pid，平台按 pid 自己读游戏退出码（这条路径 game_starter.exe 自身回 -1，不能拿来判异常） |

配套要求：

- **零交互入口**：`game_starter.exe /go` 按当前选择（含 `keymap.txt` 记忆）直接开游戏，给平台当启动命令用；
  不带参数时是交互界面，给玩家自己点。
- **参数支持**：`launcher.ini` 的 `GameArgs`（如 `-game cstrike -window`），`GameExe` 支持相对路径
  （相对游戏目录解析）；裸名字 `cmd.exe` 这种依赖 PATH 的写法在 `UseShellExecute=false` 下会失败，
  要么写全路径，要么相对游戏目录。
- **不要控制台**：`-target:winexe`；任何 `Console.*` 输出都不可依赖。
- **自测开关**：`game_starter.exe /selftest <程序> [参数…]` —— 不起界面，直接 `RunAndWait` 并回传该程序的
  退出码。没有它就只能靠真开游戏验退出码，成本高到没人验。
- **验证方法**：`Games\<游戏>\tools\host-sim.ps1`（PowerShell 版）或 `tools\HostSim.cs` → `hostsim.exe`
  （C# WinForms 版，同一套断言，四条 PASS/FAIL 直接显示在窗口上），改完启动器就跑：
  - `-Auto` / `/auto`：临时把 `launcher.ini` 指到 cmd.exe 当「假游戏」（睡 8 秒退码 7），
    不占屏跑完两条场景，结束自动还原 ini；C# 版进程退出码 = 失败项数，日志写 `hostsim-auto.log`；
  - `-Auto -RealGame` / `/auto /real`：真游戏跑，到点自己结束游戏；
  - 不带参数：开一个模拟主 GUI 的窗口，手动点「启动 / 关启动器窗口 / 强杀 / 结束游戏」走全流程。
  断言四条：① 游戏父 pid == 启动器 pid；② 关窗后启动器仍活着、游戏不受影响；
  ③ 游戏退出后启动器跟着退出且**退出码等于游戏码**；④ 强杀启动器后仍读到游戏自己的码。
  主 GUI 想拿游戏码，必须在**发现游戏进程时就 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`
  抓句柄**再轮询 `GetExitCodeProcess`——只 `WaitForExit` 启动器是拿不到游戏码的。
  认游戏子进程要按 `launcher.ini` 的 `GameExe` 匹配，别把启动器先起的 `keymap.exe` 当成游戏（踩过）。
- **外挂型游戏（汉化外挂是必需启动器的）例外**：直接子进程只能是外挂（如 DFBHD 的
  `汉化外挂.exe` → `dfbhd.dat`）。做法：`Process.Start` 外挂（`UseShellExecute=false`）；
  按 `launcher.ini` 的 `GameProcess` 进程名找到真正的游戏进程（用启动时间过滤旧进程）；
  等游戏退出并把**游戏的退出码**回传；文档写清“游戏不是启动器的直接子进程”，平台若强依赖
  直接子进程，这是外挂限制。参考 `Games\DFBHD\src\Launcher.cs`。
  Git Bash 会把 `/auto` 当路径转换掉，要么 `MSYS_NO_PATHCONV=1 ./hostsim.exe /auto`，要么写 `//auto`；
  退出码 0 只代表「无失败项」，要再看一眼日志确认它真跑过。
- **平台入口二选一**：
  - 首选 `game_starter.exe /go`（winexe 天生无控制台），平台直接把它当游戏程序；
  - 平台只认脚本时，用 **`game_starter.bat /go`**：跳过菜单、按默认项由 bat 自己启动游戏（阻塞等待），
    退出码天然回传。菜单版 bat 的写法（同选项、同默认值）：
    ```bat
    @echo off&color 4f
    setlocal
    set "tl=<原游戏名>"
    title %tl%
    mode con: lines=32 cols=92 >nul 2>&1
    if exist "%~dp0_tools\nircmd\nircmdc.exe" "%~dp0_tools\nircmd\nircmdc.exe" win center ititle "%tl%"
    cd /d "%~dp0"
    set "sel=1"
    if /i not "%~1"=="/go" (
      cls
      echo   1  启动游戏（默认）
      echo   2  启动游戏（备用配置）
      set /p "sel=  请选择 [1-2]，直接回车 = 1: "
    )
    set "sel=%sel: =%"
    if "%sel%"=="2" ( <按选项改配置> ) else ( <恢复默认配置> )
    "%~dp0<游戏.exe>" >nul 2>&1
    set "rc=%ERRORLEVEL%"
    <恢复默认配置>
    exit /b %rc%
    ```
    **坑 1**：`if ... echo a&echo b` 里的 `&` 不受 `if` 管，会无条件执行——多行提示要放进 `( )` 块。
    **坑 2**：`set /p` 必须放在块里/独立行，块里不要再 `%sel%`（解析期展开），判断放到块外。
    game_starter.exe 的 `/hideparent` 仍保留：有人把 exe 挂到 bat 后面时用它藏掉父控制台
    （只对 `cmd`/`powershell`/`pwsh` 动手），藏窗口不要依赖 nircmd/PowerShell。
    菜单版 bat **本身就是控制台窗口**，居中用 `_tools\nircmd\nircmdc.exe`（`if exist` 保护，
    放在 `title`/`mode con` 之后）；nircmd 只负责居中，不用来藏窗，缺了不影响启动。
- 启动器界面里没有「退出游戏」这种按钮：关启动器 ≠ 关游戏，脚注要写明白
  （`关窗=隐藏陪跑，游戏退出后自动回传退出码`）。

  **主窗口不许为塞长表撑大**（战神3 曾撑到 1340×880，已回归 900×620）。
- 默认游戏自动检测画面；画面不对再让玩家选固定桌面分辨率。
  不要把「备份 / 直接启动 / 自动检测（重置）/ config」写进界面。
- 只有确实需要更多兼容模式时才增加下拉选项；选项只说玩家能懂的结果，不做「将启动」摘要回显，
  也不要弹层/对话框。
- 一个启动器同时管「游戏端 + 服务端」时，中栏分上下两个 groupbox：游戏端在上、服务端在下，
  「打开运行日志 / 退出」放两组中间；服务端配置同样用下拉框，并注明服务端是给专门开服场景用的、
  模板已配好、一般玩直接用游戏端。分组的关键注意事项用「注意：…」一行写在 groupbox 标题下，
  别只藏在右栏长文里。参考实现：`Games\CS16\src\Launcher.cs`。
- **状态指示全窗口只留左下角一个**（`● 已就绪`）。标题带右上角的角标、左下的"兼容层就绪
  ddraw.dll"这类技术状态都算重复，出错时才把那句换成人话 + 下一步。
- **页脚中间固定显示 `YunGame` 品牌字样**：`fBrand`（12pt 粗体）、`Gold`（亮金），与状态/提示同一行且居中，
  不能被左右文字挤掉；这是交付品牌标识，不要换成游戏名或技术名。
- **品牌防改（分层，不宣称绝对安全）**：exe 内不要出现明文 `YunGame`；用 XOR/编码字节在
  运行时拼出，并对拼出的字符串做 SHA-256 校验；校验失败弹提示后退出。构建后运行
  `scripts/write-launcher-hashes.ps1` 生成 `game_starter.sha256`，平台可用它复核 exe；
  正式发行建议再加 Authenticode 签名。签名/哈希只能提高门槛，不能阻止有决心的逆向。
- 右栏键帽跟随当前按键方案重绘，下面接「提示」（含完整秘技）——主反馈 + 主记忆点都在这里。
- 窗口保持基准 `900×620`，**不要为了塞文案越撑越大**。右栏内容多时**用滚轮滚动**
  （按整行排版、只画视口内的行 + 细滚动条），左栏 ≤18 行；放不下先滚动/删文案，**不许**缩字号到 9pt 以下。
  内容多到滚动都难查时按硬约束 20 拆独立窗口：那边靠**加宽 + 两列 + 去标题 + 压短说明**
  争取一页看全，不靠缩字号，也不靠单列长条。
- **同一窗口所有文字用同一种渲染：TextRenderer（GDI ClearType）**，左/中/右、页眉页脚、按钮一致；
  不要全窗改 GDI+ 灰度（整体发虚），也不要把右栏画进离屏位图（ClearType 二次合成会重影）。
- **右栏滚动**：按整行排版，只画完整落在视口内的行（不做裁剪、不做位图）；一行放不下就拆成两行，
  绝不能让 cx 重置造成叠字（放不下就停止该行）。参考 `Games\CS16\src\Launcher.cs`、
  `Games\DFBHD\src\Launcher.cs` 的 `DrawRight` / `DrawWrappedVisible` / `DrawLegendRows`。
- 折行函数按字符断，中文会断词（`Esc 退\n出`很难看）：**每条独立信息自带 `\n`**，
  别用空格把好几条拼成一行让折行去切；折行只当兜底。
- 主窗口 `FixedDialog` + `MaximizeBox=false`，`StartPosition=CenterScreen`
  （硬约束 20 拆出去的独立详细窗口反过来要 `Sizable` + `MaximizeBox=true`）。

### 文案规范（统一，2026-11-01）

所有 `game_starter.exe` 的**栏目名称、顺序、用词**一致；内容按游戏替换，不许分叉：

| 位置 | 固定文案 | 说明 |
|---|---|---|
| 左栏标题 | 关于这款游戏 | |
| 左栏底部 | 玩不了或报错 → 点「打开运行日志」 → 把内容发给我们 | 不写“玩不动了”“维护人”“管理员” |
| 右栏顺序 | 进游戏说明 → 操作说明 · <按键方案> → 提示 | 不写“进游戏怎么用” |
| 中心 | 画面模式/显示 → 按键方案 → 存档/级别 → 启动游戏 → 打开运行日志 → 退出 | 按游戏可增减，顺序固定 |
| 状态栏 | 已就绪 / 游戏退出后本窗口自动关闭 | |

- **秘技/关键提示必须全文写进界面**：触发方式、每条代码、效果都要写清楚；
  **禁止写“完整秘技见某文件”这种指路废话**。内容多就用右栏滚轮滚动（窗口保持 900×620），
  或按硬约束 20 用「详细按键」按钮开独立窗口（界面内导航不算指路废话），不要把主窗口撑大。
- **所有按键一律用通用拟物键帽库**（硬约束 17，规范 `references/keycaps.md`）：
  PC / PS / Switch / Xbox 的键都走 `templates\Keycaps.cs` 的同一套标准件，
  操作说明、秘技/提示里出现的键都不能写成普通文字，也不能各游戏临时画。
  一个键帽只装一个键，多键 / 组合键画成多个独立帽；**手柄键同样画成拟物键帽**
  （旧「键帽只给真正的键盘键、鼠标/手柄用普通文字」的规定已作废）。
  不是按键的东西（提示、状态、平台名）不套键帽。
  键帽只是 GDI+ 画的形状（圆角/高光/底部厚度），键帽里的字仍用普通 TextRenderer（ClearType）；
  **不要因为键帽去改灰度/离屏位图/特殊抗锯齿**——键帽样式和文字渲染是两件事。
- **用词统一**：发给我们（**不写「管理员」「维护人」**——客户机上没有这个角色，也不指挥任何人动手，
  见 AGENTS 规则 36）、玩不了或报错（不是玩不动了）、
  进游戏说明（不是进游戏怎么用）、提示（“秘技”只作副标题）。
- **界面不出现技术串**（`rc=`、`0xC0000005`、`ddraw.dll 已就绪`），技术细节进 `运行日志.txt`。
- **左栏不出现技术名词**（Mesa / D3D12 / OpenGL / 驱动名）：玩家只看游戏介绍和「玩不了或报错」；
  兼容层说明只写“画面已适配新系统、直接进游戏”。缺层时界面只说“缺少兼容文件，请先双击 兼容修复.bat”。
- 参考实现：`Games\JustCause\src\Launcher.cs`、`Games\RoadRash\src\Launcher.cs`。

## 交互与可访问性

- 鼠标：行/按钮 hover 变亮，`Cursor=Hand`；点击即选中，主按钮点击才启动游戏。
- 键盘（必须做，自绘不等于放弃键盘）：`Tab` / `Shift+Tab` 走「启动选项 → 启动 → 修复 → 日志 → 退出」；
  下拉框（`Panel` 子类）默认不可聚焦，Tab 链要靠窗体 `ProcessCmdKey` 自己串：给下拉框留一个焦点序号、
  `DrawCenter` 里给它画焦点环、`RepaintControls` 连它的区域一起失效。
  **焦点在下拉框上时 `↑` / `↓` 直接换项**（不用先弹菜单，这是玩家最容易理解的走法），
  `Enter` / `Space` 展开 `ContextMenuStrip`，菜单内 `↑↓` + `Enter` 照常可用；
  焦点在自绘按钮上时 `Enter` / `Space` 激活、`Esc` 关窗；焦点环必须看得见。
- 反馈只在状态变化时给：选中态、启动中（按钮文字变「游戏运行中…」并禁用）、
  退出后状态行回写。**不做装饰动画、不做逐卡淡入。**
- 对比度：`Ink` 在卡片上 ≥ 4.5:1；金色按钮上的字用深棕 `OnGold` 不用黑。
- 状态不能只靠颜色表达（点 + 文字成对出现）。
- 错误文案说清「哪坏了 + 下一步做什么」：
  `兼容层缺失，请先双击 兼容修复.bat`，不要 `启动失败`。

## 下拉框（启动方式）

启动方式默认用下拉框，只放两个玩家能懂的结果：`游戏自动检测（推荐）` / `固定桌面分辨率`；
不要写「备份 / 直接启动 / 自动检测（重置）/ config」这类技术选项。其他设置（按键方案、存档）
只有确实需要时才加下拉框。
这台机器上确实需要玩家手动挑画面（如英雄无敌3 的六个实测档位）时才可以多放几项，
命名按下面「选项名字怎么起」的规则走。

**先讲清楚这个框是干嘛的**（硬约束 18）：玩家看到「启动选项」不知道它是用来救场的，
闪退了也不会想到换一档。**说明固定在下拉框的上方面、紧贴框**，
「启动选项」标签 → 说明 → 下拉框，不放到框下面、也不并到「启动说明」标题下。
固定文案（用户定案，原句照抄）：
`本下拉框的作用是：如果有闪退等异常，换另一种模式，再启动游戏试试。`
前缀「本下拉框的作用是：」不能省，否则玩家不知道这句在说哪个控件。
战神3 的做法：`CenterNote` 只留标题下的「游戏会自动检测画面。」，另用 `ComboHint`
存这句用途说明，`MeasureComboHintHeight` 按栏宽折行算高度，标签 / 说明 / 框 / 按钮顺移，
不重叠、不另拉空白；**四处对齐**（源码默认值 + src / payload / 游戏目录 ini）。
不写「切换渲染模式」「请尝试备用配置」这种技术腔，也不写「换一档就好了」这种保证。

- 不要用原生 ComboBox 的 `OwnerDrawFixed` / `FlatStyle.Flat` 半自绘组合——换主题色后容易闪；
  要么接受系统外观（白底黑字），要么完全自绘。
- 完全自绘用双缓冲 `Panel`（`UserPaint | AllPaintingInWmPaint | OptimizedDoubleBuffer`）
  + `ContextMenuStrip`（自定义 Renderer）：面板画背景/文字/箭头，菜单画深色条目；
  hover/展开只刷局部，父窗体不要整窗 `Invalidate()`。
- 原生 ComboBox 只设 `Font` / `BackColor` / `ForeColor`、绘制交给框架时，交付前必须人眼确认不闪；
  半自绘（OwnerDraw + Flat）在深色主题上最容易闪，直接避开。
- 父窗体 hover / 选中变化只刷按钮区（`Invalidate(ButtonsRect)`），不要整窗重绘。

### 弹层必须把每一项显示全（框宽不动）

**横向和竖向都要显示全**（用户定案 2026-11-04）：弹层宽度 ≥ 最长一项的文字宽度，
弹层高度 ≥ 项数 × 行高——`ComboBox` 默认只露 5 行半，第 6 项要点开滚动才看见，同样算缺陷。
只加宽/加高**弹层**，**框本身的宽度/位置不许动**（动了整栏布局就歪）。
**皮革主题优先用自绘 `SelectPanel` + `ContextMenuStrip`**：原生 ComboBox 的白底框、白底弹层和系统蓝高亮
跟皮革主题不搭（英雄无敌3 就是先用了原生控件、改皮革时才发现突兀，2026-11-04 换成自绘）。

- 原生 `ComboBox`（`DropDownList`）：设 `cb.DropDownWidth` / `cb.DropDownHeight`，不要改 `cb.Width`。
  在**布局完成之后**再算（`PlaceCombo` 之前 `cb.Width` 还是默认的 121，量出来不可信）：

  ```csharp
  int widest = 0;
  using (Graphics g = CreateGraphics())
      foreach (string s in items)
          widest = Math.Max(widest, TextRenderer.MeasureText(g, s, cb.Font).Width);
  int want = widest + SystemInformation.VerticalScrollBarWidth + S(30);
  int cap = Screen.FromControl(cb).WorkingArea.Width - S(24);   // 别超屏
  cb.DropDownWidth = Math.Max(cb.Width, Math.Min(want, cap));

  cb.MaxDropDownItems = items.Length;                             // 默认 8，但高度仍可能被截
  int ih = cb.ItemHeight > 0 ? cb.ItemHeight : S(19);
  int needH = items.Length * ih + 4;
  if (cb.DropDownHeight < needH) cb.DropDownHeight = needH;
  ```

- 自绘 `SelectPanel` + `ContextMenuStrip`：给菜单设 `menu.MinimumSize = new Size(want, 0)`
  （`want` 同上，用 `LeatherMenuRenderer` 的字量），`SelectPanel.Bounds` 保持不变；
  条目多时靠 `MaximumSize` 保证一屏能看全，不要出现半行。
- 每次启动往 `运行日志.txt` 记两行自检，报障时一眼能看出是不是又被截了：
  `下拉宽度自检：框宽=264，最长项文字宽=243，DropDownWidth=290，能装下=True`
  `下拉高度自检：项数=6 行高=19，DropDownHeight=118，能装下=True`。
- **取证只能 `PrintWindow` 自己的窗口**：截图脚本按进程 pid 找主窗口 + `ComboLBox` 弹层
  （WinForms 类名带后缀，用 `Contains("COMBOBOX")` 这种关键字匹配，别写死 `ComboBox`），
  分别 `PrintWindow(PW_RENDERFULLCONTENT)` 后按相对坐标合成。
  **不要 `CopyFromScreen` 截全屏再裁**——桌面上别的窗口（用户的浏览器等）会一起进证据里，
  已经踩过两次；展开下拉用 `SendMessage(CB_SHOWDROPDOWN)`，别用合成鼠标点击（坐标一偏就点到启动按钮）。

### 选项名字怎么起（用户定案，别再自创词）

**大白话说清「这档干什么」+ 保留技术名（GDI / DX9 / dgVoodoo2）便于远程核对**，例如：

```
1  软件画面 GDI（全屏）              ← CPU 用 Windows 自带 2D 画，不碰显卡 3D 驱动
2  软件画面 GDI（4:3黑边）
3  软件画面 GDI（窗口1280×720）
4  原版640×480（窗口）
5  DX9硬件加速（全屏）              ← 交给显卡的 Direct3D9 画
6  dgVoodoo2转换（无边框全屏）
```

- **不写保证词**：「最稳」「最兼容」「画质最好」「不会崩」一律不进选项名和界面文案（用户定案 2026-11-04）。
  **是什么就是什么**——英雄无敌3 第 1 档原来叫「软件画面 GDI（最稳·全屏）」，而玩家默认点开的正是这一档，
  网吧工单 YW027 的 `0xC0000094` 就崩在这里，承诺当场变成假话。稳不稳由程序兜
  （现场快照 → 自动改档 → 重试 → 记这台机器的可用档），不靠界面许愿。
- **不要自创抽象词**：反例「稳定全屏」「直连模式」「加速模式」——听完不知道走哪条路，用户明确否过。
- **不要给玩家看不懂的词**：`auto` / `config` / `重置` / `备份` / `兼容层` 一律不当选项名。
- **新游戏要定名字时，先给 3-4 套候选让用户挑**（可以混搭），别自己拍一套就写进界面和文档；
  定下来之后界面、`game_starter.bat` 菜单、`launcher.ini` 的 `CenterNote/Tips/EntryGuide`、
  适配文档必须一起对齐。
- 名字变长时记得回头核对弹层宽度（见上一节），别让新名字被截断。

**别信"录屏量亮度"这种自证**：试过用 ffmpeg 逐帧量下拉框区域平均亮度做 A/B，
两种写法都只出 ±3 波动（鼠标指针、抓帧重复帧就够吃掉这个量），分辨不了闪烁——
测不出来的测量不要拿来当证据。

## 玩家只面对一个界面（2026-11-07 用户定案）

- 启动器自己修：层 DLL 从备份目录补、显示配置缺失自动退回一份能用的、注册表自己写。
- 修不了只说一句人话「显示文件不完整，请把运行日志发给我们」+ 日志按钮；
  **玩家提示里不许出现任何 bat 名字，也不许出现「管理员」**（AGENTS 规则 36：不指挥任何人去做第二步）。
- 崩溃自动取证：读系统自动生成的崩溃报告（`ProgramData\Microsoft\Windows\WER\ReportQueue|ReportArchive\AppCrash_<游戏exe>_*`
  里的 `.wer`），把**异常码 + 出错地址（模块+偏移）**抄进 `运行日志.txt`，报告存进游戏目录 `崩溃转储\`；
  报告是系统后台写的，**要重试几秒**再读，读不到就在日志里写明没抓到。
  **已判死、不许再试**：`DEBUG_ONLY_THIS_PROCESS` 调试器拉起（实测游戏窗口出不来）、
  `WER LocalDumps` 注册表（要动系统）——见 AGENTS 规则 35。

## 环境读数与系统状态（2026-11-07 客户机事故后新增）

- **交付标准只有一句**（AGENTS 规则 36）：游戏目录放到**任何** Win10 / Win11 机器上，点一下就能跑，
  全程不需要玩家、网管或我们再做第二步。所有异常一律由启动器自己处理掉；
  界面、日志、文档里**不出现「管理员」**，也不出现"请先运行某某"这类要人动手的话。
- **同一功能只允许一条路径**：禁止「读到正常值就跳过、读到异常才动手」这种分叉。
  本机永远是正常值，异常分支一次都不会被执行，上客户机就是第一次跑。
  刷新率统一处理：**启动前无条件设 60Hz，游戏退出后无条件还原**（一次实现、每台机器都一样）。
- **读数必须能自证**：`GetDeviceCaps` 的索引别背错（`VREFRESH = 116`，0 是 `DRIVERVERSION`）；
  `DEVMODEW` 按规范布局写全，断言 `Marshal.SizeOf == 220`；`EnumDisplaySettings` 读回来的宽高必须 > 0。
  提供 `/readings` 之类的一键读数开关，并配一个断言脚本（样板：`Games\Heroes3\tools\readings-test.ps1`）。
- **改系统状态的功能**：进入即改、退出必还，`finally` 里还原；日志同时记「改之前 / 改之后 / 还原结果」三行。
- **不许把没取到的值当 0 交出去**（AGENTS 规则 37；客户机 `0xC0000094` 整数除零就是这条没做）：
  1999 年前后的老游戏直接把环境值当除数，取到 0 就开机崩退。启动器要在启动前把每一处钉成安全值——
  刷新率（强设 60Hz）、显示宽高与 DPI（断言 > 0，异常判为不可信并落日志）、
  磁盘几何（每扇区字节 ∈ {512,1024,2048,4096}、每簇扇数 > 0、可用簇 ≤ 总簇；映射盘/大簇就换成
  游戏目录所在本地盘的几何）、计时器（高精度不可用退回 `GetTickCount`，不用 0 当分母）、
  多人网卡（跳过 radmin/virtual/vmware/hyper-v/tap/loopback 这类虚拟网卡，静默挑物理网卡）。
  **取不到就用兜底值并写一行日志，绝不留空、绝不留 0。**
- **测试要串行**：两个测试同时跑会互相改游戏目录（拷层、删配置），收尾校验会假失败，
  看起来像产品坏了，实际是自己踩自己。一条命令收尾：`tools\收尾自检.ps1`（全程不启动游戏，逐步判退出码）。
- **测试与工具不许依赖控制台代码页**（2026-11-07 踩过两次，已落成 `规范自检.ps1` 第 17 / 18 项）：
  要断言中文结论 → 让程序把结论**另存 UTF-8 文件**再读（样板 `game_starter.exe /wer <wer> <out.txt>` +
  `tools\wer-test.ps1`），别解析 stdout；会输出中文 / 写记录文件的 bat 开头必须 `chcp 936 >nul`，
  否则从 pwsh 7（65001）调用时 `交付记录.txt` 会被写成乱码文件名，下次撤回直接找不到记录。

## 运行日志（玩家报障的唯一入口）

界面上不解释技术，全写进游戏目录的 `运行日志.txt`，玩家点「打开运行日志」用记事本打开，
截图或整个文件发回来即可定位。

- 一行一条：`yyyy-MM-dd HH:mm:ss  事件`，UTF-8；文件不存在就先写一行说明头。
- 必记的事件：启动（带参数与当前三项选择）、点「启动游戏」、画面模式切换、
  存档摆渡结果、按键方案写入结果与 rc、**游戏退出码（写成 0x%X8）**、
  关窗转后台、缺文件/异常（异常记 `ex.ToString()` 带堆栈）。
- 体积自保：超过 ~200 KB 就只保留最后几百行，别把玩家磁盘写满。
- 日志里可以出现 `rc=2`、`0xC0000005` 这类技术串；**界面文案不行**。
- 提权失败、注册表写不进、`reg import` 返回码这些都要落日志，否则远程无从判断。

## 体积与构建

```bat
csc -nologo -target:winexe -optimize+ -platform:anycpu -codepage:65001 ^
    -r:System.Windows.Forms.dll -r:System.Drawing.dll ^
    -out:game_starter.exe Keycaps.cs Launcher.cs
```

- `Keycaps.cs` 是 `templates\Keycaps.cs` 的整份拷贝，所有平台共用；接入三步见
  `references/keycaps.md` §2。缺了这一行会编译报「找不到 Keycaps」。

- `-codepage:65001`：源码 UTF-8，否则中文字面量在 cmd 下会乱。
- 不加 `-debug`（默认 release 无 pdb）；`-optimize+` 省几 KB。
- 想要高分屏不糊：加 `-win32manifest:app.manifest`（`dpiAware=PM`），代价约 1 KB，
  同时所有尺寸必须走 `S()`；不加也能用，只是 150% 缩放下由系统拉伸略糊。
- **统一启动器图标**：固定 `csc -win32icon:D:\ico.ico`；运行时取 exe 自身图标。
  不要再从游戏 exe 抽图标（会被当成游戏进程）。`D:\ico.ico` 缺失时构建失败；
  不要把 `.ico` 提交进 `src\` 或游戏目录。
- 游戏目录里出现 `.png` / `.jpg` / `.ico` / `.resx` / `.cs` 就算违规，用检查脚本兜底。
