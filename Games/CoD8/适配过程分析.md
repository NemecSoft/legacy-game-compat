# 使命召唤8（Modern Warfare 3 · iw5sp.exe）适配过程分析

交付形态：`Games\CoD8\release\`（payload + 一键应用.bat + 一键撤回.bat），启动器 `game_starter.exe` 从 `Games\CoD7\src\Launcher.cs` 底本移植。用户指令：**和 CoD7 一样处理——兼容、绿色、通用、不再提示硬件、自动适配桌面分辨率**。

## 2026-11-10 定案

### 1. 注册表：不需要，不打

CoD8（IW5 引擎）配置全在游戏目录内：`players2\config.cfg`（单人）、`players2\save\`（存档）。没有 Heroes3 那类要写系统的注册表依赖，启动器不碰注册表。

### 2. 兼容层：**纯原生 Direct3D 9（2026-11-10 04:29 用户定案），DXVK 全部砍掉**

- 用户指令：「我已经把 CoD8 复原了，不要打 dxvk 补丁了」——启动器只留原生 D3D9 一档，游戏目录根不出现任何 d3d9.dll/dxgi.dll/dxvk.conf，`_dxvk\` 留底也清掉，release payload 同步精简。
- 早期 DXVK 双档实测记录保留在 `evidence\`（sp-dxvk-probe.png 等）作取证，交付不再含 DXVK。
- 画面设置由引擎读写 `players2\config.cfg`；分辨率自适应账本（第 3 节）在原生档下同样工作。

### 2.5 启动方式（2026-11-10 深夜定案，本作最大坑）：`cmd start /D 钉死工作目录`

实测教训链（全部当天踩到）：

| 启动方式 | 结果 | 原因 |
|---|---|---|
| CreateProcess 直连（工作目录=游戏目录） | 用户报黑屏 | 用户双击正常、此路不正常，原因未完全定论，弃用 |
| explorer.exe 命令行拉起 | 弹「不能加载 localization.txt」 | **explorer 拉进程时工作目录继承 explorer 自己的（system32/桌面），不是游戏目录**；双击才会把工作目录设成文件所在文件夹 |
| `cmd /d /c start "" /wait /D "游戏目录" "exe"` | **用户实测正常** ✅ | start 内部就是 ShellExecuteEx（双击同路），`/D` 显式把工作目录钉在游戏目录 |

- 根因：IW 引擎全靠相对路径找资源（`localization.txt`、`main\`、`zone\`），工作目录一错引擎早期就死或弹错误框。
- 陪跑/移交/点框/看门狗全部按**进程名**（`s_gameExe`）找游戏 pid，不依赖父子关系；退出码取游戏本体进程，cmd 只是启动跳板。
- 前台移交、安全模式标记清理、首次画面规范等其余逻辑与 CoD7 同构。

### 3. 分辨率自适应：复用账本机制，但变量名是 IW5 的

与 CoD2/CoD7 同一套 display.state 账本：没记录 → 首次规范「全屏 + 本机实测桌面分辨率」；值还是我们写的 → 每次按当前桌面刷新（换显示器照样全屏）；玩家改过 → 永远不再动。

CoD8 的差异（照搬 CoD7 就会写错）：

| 项 | CoD7 | CoD8（IW5） |
|---|---|---|
| 全屏变量 | `r_fullscreen "1"` | `r_displayMode "fullscreen"`（字符串） |
| 配置目录 | `players\`（用户目录也有） | `players2\`（只在游戏目录） |
| 画质档 | 多档 dvar | `r_imageQuality`：**0=Native**，其余档是 720p 放大——交付取 0 |
| 进程优先级 | `r_autopriority "1"`=高优先 | `r_autopriority` 语义**相反**：`0`=High Priority（社区证实），交付取 0 |
| 开场动画 | — | `seta intro "0"` 跳过 |

首次规范写入 6 项交付默认（`PerfDefaults`）：`intro|0`、`r_preloadShaders|1`、`r_imageQuality|0`、`r_autopriority|0` + 画面两项（fullscreen / 桌面分辨率）。**不碰任何 bind 键位行**——玩家键位一律保留。

### 4. 「不再提示硬件/安全模式」：删标记，不打补丁

- 异常退出标记是游戏目录根的 4 字节文件 `__iw5sp`（IW5 是老布局，与 CoD2 同类；CoD7 的在 `%LOCALAPPDATA%` 是新布局——两代引擎位置不同，别混）。
- 启动器每次启动前静默删标记并写日志，`--clearmark` 开关可单独验证。
- 本作**没有**照 CoD2 打字节补丁（无 `_orig\`）：删标记已覆盖启动器路径；玩家直接双击 exe 的场景，本作弹框不降画质危害小，按「最小改动」原则不动主程序。

### 5. 通关存档：机制与 CoD7 完全不同，零配套脚本

用户已放置通关存档并确认：存档是 `players2\save\*.svg` 整包（17 个关卡 svg + `autosave\` + `internal\`），引擎直接按文件读。

- **没有** CoD7 的 `sv_lastSave*` 指针、**没有** `mis_01` 解锁键——CoD7 那套 SaveAutoFix/SaveUnlock/SaveFile 全部砍掉，不适用。
- 实证：2026-11-10 03:20 用户跑游戏后 `save\autosave\` 正常新增 `sp_intro-levelend.svg`、`sp_ny_manhattan.svg`，说明引擎读到了存档并继续写档，存档闭环成立。
- 用户改过的 `config.cfg`（含键位）启动器不会覆盖：显示账本比对的现值与记录一致（`fullscreen|1920x1080`），走「跟机刷新」且文件零改动；bind 行任何分支都不碰。

### 6. 端到端验证（--go 零交互）

- 验证通道按坑 98/101：pwsh `Start-Process -ArgumentList '--go'`，日志核对「启动参数=原始 --go」「零交互：是」。
- DXVK 档 --go 实测：游戏拉起、1080p 全屏主菜单、无弹框（`evidence\launcher-go-dxvk.png`）。
- 幂等复跑：重复 --go 退出码 0，config 无多余改动。

### 坑与教训

1. **`r_autopriority` 照搬 CoD7 的 1 是反的**：IW5 里 0 才是 High Priority。同系列不同引擎版本，同名义变量语义可能相反，必须逐项用本机实测 + 社区来源核对，不许按上一作的经验默认。
2. **`r_imageQuality "3"` 不是低画质**：0 才是 Native，其余档是 720p 放大。画质档位的数值含义必须查证，不能按「数字大=质量高/低」猜。
3. **从同类游戏拷源码，头部「已实测确认的事实」注释块必须整块重写**：CoD8 的 Launcher.cs 开头一度还是 CoD2 的取证描述（`main\players\3dm`、`r_fullscreen`、`__CoD2SP_s`），代码对、注释错，后来者按注释理解必错（坑 105）。
4. **通关存档机制按引擎查证再动手**：IW3（CoD7）是「config 解锁键 + svg 指针」两半；IW5（CoD8）是 svg 整包直读。把上一作的存档修复逻辑搬过来纯属多余且有害。
5. **老引擎启动必须钉死工作目录（坑 106）**：explorer 命令行拉起 ≠ 双击——双击把工作目录设为文件所在文件夹，explorer 拉起继承 explorer 的 CWD。「不能加载 localization.txt」这类弹框就是工作目录错的诊断金线索。正解 `cmd /d /c start "" /wait /D "<游戏目录>" "<exe>"`。
6. **排查黑屏先劈「启动方式」再查别的**：本作黑屏曾先后误判成 DXVK、r_preloadShaders、存档、虚拟显示器、联网校验——实际第一现场是启动方式与工作目录。用户报「双击正常、启动器黑屏」时，差异点就是启动路径，别往显卡/网络扯。

### 启动方式复验翻案（05:16-05:22，2026-11-10 深夜）

用户点名「用 win32 再启动一次试试」，复验结果推翻两处旧结论：

1. **CreateProcess 无责**：干净 CreateProcess（lpCurrentDirectory=游戏目录）直连 iw5sp.exe，主菜单正常渲染（evidence\repro-win32-t10s.png）、60 秒全程存活响应正常（repro-win32.ps1 带 -KeepOpen 复测）。当年「CreateProcess 黑屏」根因就是工作目录没设对，外加 DXVK 残留干扰判断——用户从头判断正确（「只是你原来 CreateProcess 工作目录不对」）。
2. **「20 秒退出、退出码 -1」是试验脚本冤案**：capture-window.ps1 截完图默认 Stop-Process 强杀目标进程（坑 111），观察型脚本没传 -KeepOpen 亲手杀了试验对象；-1 是强杀特征码，却被当成游戏/壳退出码，还编出「3DM 壳联网校验」的不存在故事——用户「单机断网一样能玩」一句戳破。

处置：启动器保持 cmd start /D 不动（用户实测玩过一局，且两条路本质都是钉对 CWD，用户拍板不改）；坑 96 追加复验翻案、坑 106 修正「CreateProcess 弃用」表述、新增坑 111。
