# 虐杀原形2 Prototype 2 适配过程

## 目录与启动链

- 游戏：`D:\YunGame\Prototype\Prototype.2`（实际目录带点），简体中文硬盘版，主程序 `prototype2.exe`。
- 游戏目录原有 `go.bat` 保留不动；它当前的有效链是：直接启动 `prototype2.exe`，并用
  `start /affinity 0x3ff /wait`；其中 `./init.exe` 这一行在 cmd 里报错，但游戏不依赖它也能正常启动。
- 因此启动器设 `RunInit=0`，严格按有效链直接启动游戏；不修改 go.bat。
- 兼容层：`d3d9.dll` 为 DXVK，`dxvk.conf` 为原配置；`_dxvk\` 已留底（d3d9.dll + dxvk.conf）。
- 存档：不复制、不写存档位置；由游戏自己管理（启动器不碰 `我的文档`）。

## 亲和性

- 与 go.bat 一样使用 `0x3ff` 亲和性；启动器用 `CreateProcess(CREATE_SUSPENDED)` + `SetProcessAffinityMask`
  后再恢复线程，游戏是启动器的直接子进程。
- **启动器不加任何分辨率/窗口参数，不写游戏设置**。黑边/宽高比/人物比例请在游戏内
  「选项」里设置；之前测试中出现的画面差异来自另一次测试启动方式，不作为交付链路。

## 为什么用 DXVK 2.3.1，不用 dgVoodoo2

- 本机 dgVoodoo2：UI 洋红、pure3d 引擎 `CreateVertexBuffer` 断言 `mVBO != 0` → `0xC0000005`；
  D3D12 后端退出。换 DXVK 2.3.1 后洋红 0%、可正常进游戏（`references/cases.md` 第 2 节）。
- AMD 驱动缺 `VK_KHR_load_store_op_none`，DXVK 3.x 找不到适配器，锁 2.3.1。

## 实施阶段 HUD（证明走的是 DXVK，不是显卡原生）

- 与 P1 相同的 DXVK `d3d9.dll`（4,046,862 字节）；取证时临时 `DXVK_HUD=version,api,fps`，
  `devinfo` 只显示 RX 580，不能当层证据。
- 交付 `dxvk.conf` 写 `dxvk.hud = fps`，当前实测 `evidence/prototype2-fps-only.png`
  左上角只有 `FPS: 59.9`；启动器不写游戏设置。

## 启动器

- GUI `game_starter.exe`：900×620 三栏、规范红渐变、正常 TextRenderer ClearType；
  中栏启动游戏/日志/退出；右栏进游戏说明、操作说明（键帽）、提示（可滚轮）；左栏游戏介绍。
- 控制台版 `game_starter.bat`：菜单 1 启动 / 2 日志 / 3 退出，`/go` 零交互；启动前按 go.bat
  直接以 0x3ff 亲和性启动，不检查/复制存档。
- 构建：`Games\Prototype2\build.ps1` → 31.5 KB；构建时从 `prototype2.exe` 抽图标并 `-win32icon` 嵌入，
  文件图标与游戏图标一致。
- `兼容修复.bat` / `恢复原版.bat`：恢复/移除 DXVK；游戏、汉化、go.bat 均未动。

## 证据

- `evidence/prototype2-launcher.png`：启动器界面。
- HUD 截图待补：取证时用户正在使用电脑，游戏窗口被其他程序遮挡/提前关闭，不把无效截图留在
  `evidence/`。P2 与 P1 的 `d3d9.dll` 是同一个文件（4,046,862 字节，DXVK 2.3.1）；
  P1 的 HUD 证据为 `Games\Prototype1\evidence\prototype1-hud.png`（`DXVK v2.3.1 / D3D9 / 59.9 FPS`）。
  用户实机确认 P2 可正常进游戏。
- 游戏启动链以游戏目录 `go.bat` 为准；启动器不覆盖分辨率/画质/存档，也不传额外参数。
