# 使命召唤4：现代战争 重制版 —— 启动器适配过程分析

## 1. 这次要做什么，后来怎么变了

- 起点（用户）：给 `D:\YunGame\CoD\CoD4.Remastered` 做启动器，「加一个英文的，看看有没有繁体中文的」。
- 调研结论：这个整合包切不动语言，也没装繁体包（详见 §2）。
- 用户定案（2026-11-12）：「不切语言了」「就搞一个启动器就行了」。
- 最终交付：一个**不带语言切换**的标准启动器，游戏保持整合包自带的简体中文，启动器不碰任何语言设置。

## 2. 语言调研：为什么最后不切了（全靠实测，不是猜）

目录情况：

- 主程序 `h1_sp64_ship.exe`，是 CODEX / Steam 模拟器整合包，不是战网版。顶层两个 ini 还互相打架：`steam_emu.ini` 写 `Language=english`，`CONFIG.ini` 写 `Language=schinese`。
- 语言包目录只有 `english` 和 `simplified_chinese`（约 1.2G），**没有繁体包**。主 exe 里能搜到 `traditional_chinese` / `tchinese` 字样，说明游戏本体认繁中，但这份整合包没装。
- `C:\Users\Public\Documents\Steam\CODEX\393080` 存档目录是当天的，真正在跑的是 CODEX 模拟器。

做过的对照实验（共 11 组，每组真启动游戏、抓主菜单画面，图在 `evidence\probe*.png`）：

| 组 | 改了什么 | 主菜单实际显示 |
|---|---|---|
| 1 | 两个 ini 都设 `schinese` | 简体中文：战役／新游戏／任务选择／选项 |
| 2 | 两个 ini 都设 `english` | 还是简体中文 |
| 3 | `steam_emu.ini=schinese`、`CONFIG.ini=english` | 还是简体中文 |
| 4 | 两个 ini 都设 `tchinese` | 还是简体中文，没有繁体字 |
| 5–8 | 改 `HKCU\Software\Valve\Steam` 的 `Language`（原值 `schinese`）为 `english`，再配上 ini 各种组合 | 还是简体中文 |
| 9–11 | 进程级语言环境变量、命令行 `+set language` 等 | 还是简体中文 |
| 决定性一组 | 把 `simplified_chinese` 目录改名藏起来 | 游戏直接起不来 |

结论：这份整合包把简体中文做进了文件层，语言**不是** ini / 注册表 / 环境变量 / 命令行的开关；改这些都是白改。想加英文或繁体，得换装了对应语言包的版本，不是启动器能解决的。

判死记录已写进 `references\do-not-retry.md`，`scripts\规范自检.ps1` 第 9 项会拦住重新引进语言开关的代码（规则 33）。

## 3. 现场恢复

- 实验前留了底：`backup\steam_emu.ini.原版`、`backup\CONFIG.ini.原版`。
- 收尾按留底恢复：`steam_emu.ini=english`、`CONFIG.ini=schinese`；注册表 `HKCU\Software\Valve\Steam` 的 `Language` 保持 `schinese`；语言包目录和 `players2` 存档没动；没有残留进程。
- 5 个语言探针脚本**没删**，归档到 `evidence\语言实验脚本\`。它们内联了全屏截图，放在 `tools\` 会被规范自检第 15 项报；现在只作为调研留档。

## 4. 启动器方案

- 交付物：游戏目录里 `game_starter.exe`（42 KB）、`game_starter.sha256`、`使用说明.txt`。按规则 27 只做 exe，不新写 bat；整合包自带的两个 bat 保持原样。
- 界面：三栏 900×620 拟物皮革。左「关于这款游戏」、中「准备开玩」（一句说明 + 启动游戏／打开运行日志／退出）、右「操作说明」12 行拟物键帽。
- 键位来源：`players2\keys.cfg`（游戏自己的默认绑定），键帽走 `templates\Keycaps.cs` 通用库，鼠标左右键也画成键帽。
- 启动：`Process.Start` 直接起 `h1_sp64_ship.exe`（`UseShellExecute=false`），游戏是启动器的直接子进程；启动器藏到托盘陪跑；游戏一退出，启动器立刻退出并原样回传退出码；关窗只是隐藏，不杀游戏。
- 窗口零干预（规则 44）：不碰游戏进程的窗口，不抢前台、不还原最小化，全屏切换交给游戏自己。
- 不碰语言：启动器不写 ini、不写注册表、不改任何语言文件。
- 运行日志：记启动参数与零交互标记、现场读数（桌面分辨率／刷新率／DPI／磁盘几何，都带区间断言）、点「启动游戏」、游戏 pid、退出码（十六进制）、用时、关窗转后台、异常堆栈；超过 200 KB 自动只留最后 300 行。
- 崩溃取证：退出码非 0 时重试几秒扫系统自动生成的 WER 报告，按**中英文两套字段名**取异常码／出错地址／故障模块抄进日志，报告本体复制进游戏目录 `崩溃转储\`；读不到就如实写「没抓到」，不伪造。
- 开关：`--go`（平台零交互入口）、`--selftest <程序>`（退出码回归）、`--wer <报告> <输出>`（崩溃解析回归）、`--hideparent`。`--xxx` 归一化成 `/xxx`，老平台配置写 `/go` 也照认（规则 42）。
- 其它：统一启动器图标、窗口居中、exe 内品牌编码字节 + SHA-256 自校验、构建生成 `game_starter.sha256`。

## 6. 自净（成长四件套，规则 38）

1. **会红的检查**：`scripts\规范自检.ps1` 第 9 项新增 `CoD4Remastered` 判死模式——谁再把 `steam_emu` / `CONFIG.ini` / `Valve\Steam` / `tchinese` 相关代码写回启动器源码，自检直接报红。
2. **规范约束**：`references\do-not-retry.md` 新增两行，把「改 ini / 注册表 / 环境变量 / 命令行切语言」和「给这台整合包加繁体选项」判死，只在这一处权威来源写（规则 33）。
3. **自动处理 / 取证入口**：`tools\go-test.ps1`（假游戏验零交互，不拉真游戏）、`tools\exitcode-test.ps1`、`tools\wer-test.ps1`、`tools\界面自检.ps1`；启动器自带 `--selftest` / `--wer` 两个不开界面的开关，崩溃报告自动抄进运行日志和游戏目录。
4. **下次省掉哪一步**：下次遇到 CODEX 整合包要切语言，先查 `references\do-not-retry.md`、再看游戏目录里实际装了哪几个语言包，不用再花 11 组实验去试 ini / 注册表；验证平台契约直接套 `tools\go-test.ps1` 的假游戏套路，不必反复把真游戏拉起来。

## 7. 已知边界

- 本启动器不改语言，游戏保持整合包自带的简体中文；英文 / 繁体需要另找装了对应语言包的版本。
- 崩溃取证依赖系统自己生成 WER 报告；系统没生成，日志里就只写「没抓到」，不会编一段出来。
