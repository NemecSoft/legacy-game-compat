# 魔兽争霸III（Warcraft III 1.26/1.27 混合目录）—— 原生 DirectX 初始化失败

> **2026-11-01 最终结论：原生 D3D9 已修好，本机不再需要 DXVK。** 根因是注册表
> `HKLM\SOFTWARE\Microsoft\Direct3D\Drivers\SoftwareOnly=1`（64 位 + WOW6432Node 两个视图）
> 和 `DirectDraw\EmulationOnly=1`（64 位）——由“DirectX 修复工具”写入的强制软件渲染开关。
> 清除后原生 D3D9 恢复，War3 直接 1920×1080 进主菜单。详见第 7 节。

- 游戏目录：`D:\Games\War3`（XDGAME 硬盘版；`War3.exe` 1.26.0.6401、`Game.dll` 1.27.0.52240、`Warcraft III.exe` 1.0.0.1 引导壳）
- 本机：Win11 x64 / AMD RX 580 / **原生 D3D9 全面失效**（见仓库 AGENTS 的机器事实）
- 结论：**游戏目录内放 DXVK 2.5.3 `d3d9.dll` 即可，实测 1920×1080 正常进界面**；不动系统、不动驱动

## 1. 症状（用户原话：以前能玩，突然不能玩）

- 双击 `War3.exe`：无窗口，约 2.6 秒进程退出，退出码 `0x00000000`；
- 换成 `Warcraft III.exe`（1.27 引导壳）一样；
- 用户环境里 **War3 目录从 2021 年后没有任何文件改动**（`find -newermt` 为空）。

## 2. 定位过程（不猜，全实测）

| 步骤 | 结果 |
|---|---|
| 等 10 秒截图 | 什么都没抓到（游戏 2.6 秒就退） |
| 迷你调试器 `tools\procdbg.exe` 挂起启动 | 加载 `SysWOW64\d3d9.dll` + AMD UMD（`aticfx32/atiumdag/atiumdva`）→ 0.39s 后加载输入法/核心消息 → **2.65s EXIT 0x00000000**，无异常 |
| 120ms 轮询窗口 | 抓到 `#32770`（对话框类）+ 标题 `Warcraft III`，内容：**“魔兽争霸III不能初始化DirectX。请确保你的系统拥有DirectX8.1或者更高的版本以及你的显示驱动程序是最新的……”** |
| 去掉 AppCompat 标记 `DWM8And16BitMitigation` 再试 | 同样报错（已原样还原）→ 兼容性 shim 不是原因 |
| `-window` / `-swtnl` / 两者组合 | 全部报同一个 DirectX 对话框 → 不是全屏/16 位色/硬件 T&L 单独造成 |
| `D3D9Probe32.exe`（裸跑，系统 d3d9） | adapter0 全屏 `0x8876086A`、**窗口也是 `0x8876086A`**；adapter1 `0x8876086C` |

结论：**当前这台机器用系统自带 d3d9 连窗口模式设备都建不出来**，所以不只是 War3——所有 D3D9 老游戏都会这样。
（系统 `d3d9.dll`/`d3d8.dll`/`dxgi.dll` 均为 2026-09-24 更新后的 10.0.26100.9549 版本；这里只记录事实，不展开驱动层。）
`JustCause.exe` 之前也是同一个原因，只是那边已经用 DXVK 解决。

## 3. 修复：游戏目录内 DXVK（绿色）【历史方案，本机已不再需要，见第 7 节】

```
d3d9.dll          DXVK 2.5.3 (x86)   ← 放在 War3 目录，只影响本游戏
dxvk.conf         默认不开 HUD
_dxvk\            留底（d3d9.dll + dxvk.conf）
兼容修复.bat      从 _dxvk 复制上来；已有 d3d9.dll 会先备份成 d3d9.dll.原版-bak
恢复原版.bat      删除 d3d9.dll/dxvk.conf，还原备份
```

验证：启动 `War3.exe` → 出现 `Warcraft III` 窗口（1920×1080），截图 `evidence\war3-dxvk.png`
（“游戏设定”界面、中文正常、地图预览正常）；DXVK 生成 `War3_d3d9.log` 与 `War3.dxvk-cache`。

## 4. 回滚

`恢复原版.bat` 往返测过：删掉 d3d9.dll/dxvk.conf 后游戏恢复原状（再次弹 DirectX 对话框）；
`兼容修复.bat` 再装回来即可。

## 5. 复现检查清单（下次“突然不能玩”先跑这三步）

1. 别等 10 秒截图：用 `tools\war3-dialog.ps1` 轮询 `#32770` 对话框，先拿到游戏自己的错误原文；

在系统级修好之前，**游戏目录内放 DXVK 即可照常玩**（已验证，见第 3 节）。

## 7. 最终根因与修复（2026-11-01）

**根因**：`HKLM\SOFTWARE\Microsoft\Direct3D\Drivers\SoftwareOnly=1`（**64 位和 WOW6432Node 两个视图都是 1**），
另有 `HKLM\SOFTWARE\Microsoft\DirectDraw\EmulationOnly=1`（64 位）。这是“DirectX 修复/优化”类工具写入的
**全局强制软件渲染开关**，直接把 D3D9 的 HAL 设备关死；D3D9On12 同样受影响，D3D11/12/Vulkan 完全正常。
**重装/换驱动不会清除它们**，所以此前的驱动排查全部无效。

**证据**：Procmon 抓到 `d3d9.dll` 在返回 `0x8876086A` 前读取
`...\Direct3D\Drivers\SoftwareOnly`，结果为 `REG_DWORD 1`；同一探针在删除后全部 `0x00000000`。

**修复**：
1. 备份 `HKLM\SOFTWARE\Microsoft\Direct3D`、`HKLM\SOFTWARE\WOW6432Node\Microsoft\Direct3D`、
   `HKLM\SOFTWARE\Microsoft\DirectDraw`、`HKLM\SOFTWARE\WOW6432Node\Microsoft\DirectDraw`；
2. 删除上述 `SoftwareOnly` / `EmulationOnly` 值（两个视图都删）；
3. 不需要重启，直接跑 `scripts\修复本机D3D9.bat` 一键完成并自动用探针复测。

**验证矩阵（全部实测）**：

| 测试 | 修复前 | 修复后 |
|---|---|---|
| `D3D9Probe32.exe` 窗口 | `0x8876086A` | `0x00000000` |
| `D3D9Probe32.exe` 全屏 1920×1080@60 | `0x8876086A` | `0x00000000` |
| 64 位真实窗口 `CreateDevice` | `0x8876086A` | `0x00000000` |
| `D3D9On12` `CreateDevice` | `0x8876086A` | `0x00000000` |
| War3 原版（`D:\Games\War3`，已撤 DXVK） | 弹“不能初始化DirectX” | 原生 1920×1080 主菜单（`evidence\war3-main-fixed.png`） |
| War3 干净副本（`D:\Downloads\...`） | 同样报错 | 原生 1920×1080 主菜单（`evidence\war3-native-fixed.png`） |

**收尾**：`D:\Games\War3` 里的 DXVK `d3d9.dll`/`dxvk.conf` 已删除，`_dxvk\` 保留作其他机器的备选；
`War3.exe` 的 AppCompat `DWM8And16BitMitigation` 已移除（备份在 `evidence\layers-before.reg`）。
**D3D11/12/Vulkan、AMD 软件、虚拟显示器、刷新率都与本故障无关。**

## 8. 排查复盘（为什么绕了一晚上）

| 阶段 | 当时的判断 | 真相 | 教训 |
|---|---|---|---|
| 探针显示 `S_OK 0×0` | 显示模式映射坏了 | `printf` 求值顺序假象；模式一直是 1920×1080 | 先调用、再单独打印 |

| 换驱动 / DDU / 重启 | 驱动坏了 | 26.5.2 本来就是能玩的版本；开关在驱动外 | 先查全局开关 |
| 虚拟显示器 / 远程软件 / WSL / AMD 软件 / 刷新率 / KMD 值 | 逐个像嫌疑人 | 全部排除 | 用对照实验，不要靠猜 |
| `D3D9On12` 也失败 | AMD UMD 坏了 | D3D9 运行时被强制软件 | 9on12 同挂 = 运行时级开关 |
| Procmon | — | 抓到 `Direct3D\Drivers\SoftwareOnly=1` | 抓注册表读，一锤定音 |

**最关键的外部约束**：用户明确要求**不重装、不装更新、不拿驱动/显卡当结论**。
如果允许重装，开关会被“碰巧”清掉，但根因永远学不到；正是这三条把方向从“换驱动”逼回注册表和运行时。
