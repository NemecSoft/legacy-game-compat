# 使命召唤7：黑色行动（CoD7）适配过程分析

- 游戏：Call of Duty: Black Ops（Treyarch 2010），简体中文版，目录 `D:\YunGame\CoD\CoD7`。
- 主程序：`BlackOps.exe`（单人）+ `BlackOpsMP.exe`（多人，带反作弊不接），均 32 位（PE32，Machine 0x14C）。
- 交付形态：绿色启动器 `game_starter.exe` + DXVK x86 兼容层，按规则 17 打 `release\` 交付包。
- **交付定位（2026-11-10 用户强调）**：面向**任何一台 Win10/Win11 机器的任何玩家**——兼容、绿色、通用，
  不预设网吧、还原卡或任何特定环境。所有"首次规范 / 跟机刷新 / 玩家改过不动"的机制都是通用账本逻辑；
  换机器、换显示器、配置被清掉或被还原，只是它会自然覆盖的其中几种情况，不是设计前提。

## 2026-11-10 定案

### 1. 注册表：不需要，不打

- 目录里那个 `注册表.reg` 写的是 `HKLM\SOFTWARE\Activision\Call of Duty Black Ops`（InstallPath 等 6 个值）。
- 二进制取证：SP/MP 两个 exe 里**都没有**这个键名字符串（只有 `\Activision\CoD` 片段和 Steam 的 InstallPath），游戏不读它——它是安装器留的记录。
- 动态实证：本机注册表两个视图都没有这个键，游戏直接受控跑通（主菜单、45s 存活、退出码 0）。
- 结论：不打注册表（符合规则 5「不碰系统」）。以后别的游戏问「要不要打注册表」，先搜 exe 字符串再实测，别照单全收。

### 2. 兼容层：DXVK x86（原生档不可用，已实测）

- 原生 D3D9 档实测（三轮）：无论 config 写 `r_mode "1920x1080"`（exe 内确认 `%ix%i` 解析格式）、`r_mode "-1" + r_customMode`、还是命令行 `+set r_mode ...`，游戏独占全屏一律被引擎强制切回 800×600（桌面模式都被切走），退出时把 800×600 写回 config。原因未深挖（疑似 vid 初始化回退），但三条路都堵死是实测事实。
- **DXVK 档一把过**：挂 `d3d9.dll`+`dxgi.dll`（DXVK 2.5.3 x86）后，`r_mode "1920x1080"` 直接生效——交换链 1920×1080、不切系统显示模式、游戏退出把 1920×1080 原样写回 config、WM_CLOSE 退出码 0。
- 证据：`evidence\sp-native-2560x1440.png`（原生 800×600 菜单，正常渲染）、`evidence\sp-dxvk-1920x1080.png`（DXVK 1080p 菜单 + 左上角 FPS: 60.1，规则 11 挂载证据）。
- 原生档保留为第 2 档兜底（没有 Vulkan 的机器）：能进游戏玩，分辨率锁 800×600（如实标注，规则 19）。

### 3. 分辨率自适应：复用 CoD2 的账本机制

- `NormalizeDisplayDefaults` 扩展支持 CoD7 布局（`players\config.cfg`，不在 `main\players\` 下）。
- 目标值 = **启动时实测桌面分辨率**（`DesktopModeString`，规则 40），DXVK 档下生效。
- `display.state` 账本：首次规范写「全屏+桌面分辨率」；换机器/换显示器自动跟机刷新；玩家在游戏里自己改过就不再动。
- 通用性：换机器、换显示器、新玩家首次运行，或配置与账本被清掉/还原时 → 重新「首次规范」→ 自适应重新生效，自洽。交付面向任何 Win10/11 机器，不依赖任何特定环境。

### 4. 安全模式询问框：两层保险，「以后不再问」

- 机制：游戏异常退出会在目录根留 4 字节标记 `__BlackOps`（exe 内 `__%s` 模板），下次启动弹 "Run In Safe Mode?"，选「是」会降安全默认。
- 第一层：启动器每次启动静默删标记（照 CoD2 的 SafeMark 机制，SafeMark 留空自动推导）。
- **实测发现 CoD7 比候选标记更敏感**：标记不存在时它仍可能弹框（判断源不止这一个文件）→ 第二层兜底必要：启动器陪跑轮询里发现标题含 "Safe Mode" 的对话框自动点「否」（按系统语言匹配 否/No），实测两次都成功。
- 副作用记录：验证脚本强杀（TerminateProcess）游戏会加大下次弹框概率——启动器陪跑干净收尾是正路。

### 5. 字幕默认开（2026-11-10 用户要求）

- `cg_subtitles` 交付默认 0。启动器在**首次规范**（账本无记录）时顺带写成 1，此后玩家自己关掉就尊重玩家。
- 换机器 / 配置与账本被清掉或还原 → 首次规范重新触发 → 字幕重新默认开。
- 验证：模拟初始态（r_mode=800x600 + 字幕 0 + 删账本）跑 `/display` → r_mode=1920x1080、cg_subtitles=1、账本重建，退出码 0。

### 6. 端到端验证（/go 零交互）

- 日志全链路：兼容层自检 → 读数校验（1920×1080@59）→ 标记处理 → 画面默认值（一字不动只记账）→ 启动 → 前台移交 ×2 → 安全模式框自动点否 → WM_CLOSE → 退出码 0x00000000 回传。
- 游戏全程前台、桌面模式不被打扰、r_mode 保持 1920×1080。

### 坑与教训

- **规则 40 的反例就出在本游戏**：探针第一轮拿客户机快照的 2560×1440 当本机分辨率写测试，实际本机 1920×1080，整轮作废重跑（坑 97）。
- config.cfg 是引擎私有字节流（LF 换行、含本地化双字节类名）：只许字节级/Latin1 往返处理，不许 UTF-8 解码重写（坑 95 同源）。
- 游戏每次正常退出会重写 config（含把非 ASCII 类名写回）——"改了又被写回"要先分清是游戏重写还是没读到。

## 2026-11-10 社区调研：使命召唤7「很卡」的根因与优化（A 档 + 键位已落地，B/C 档未动）

### 为什么卡（对得上实机 config 的硬证据）
1. **单卡却设了多卡**：实机 `seta r_multiGpu "1"`。2010 年首发论坛实测（GamersRadio）与 SegmentNext 都写：只有 SLI/Crossfire 才设 1，单卡必须 0，改完从 <1 FPS 到 60 FPS——头号嫌疑。
2. **多核 CPU 却关了多线程渲染**：实机 `seta r_multithreaded_device "0"`。PC Gamer 2010 实测、游侠/3DM 增强设置帖、SegmentNext 一致建议多核设 1。
3. **帧率不是低，是帧时间不稳**：PCGamingWiki 确认 IW 3.0 引擎硬上限 91 FPS，`com_maxfps "85"` 是官方默认（实机正是 85），改高无效、改低只是稳帧；社区「锁 33/60/66」是为稳帧时间，不是提速。爆炸顿卡另有 `r_autopriority`（3DM 帖建议 1，实机 0）。
4. **特效大户**：PC Gamer 当年实测关 AA / 各向异性 / 阴影收益最大；PCGamingWiki 明确给关景深 `r_dof_enable 1→0`（实机 1）、运动模糊（实机已 0）。实机 `r_distortion 1` 也是大户候选。
5. **DXVK 场景新坑**：首次运行时着色器编译卡顿；`BlackOps.dxvk-cache` 就写在游戏目录（本机实测 300 KB）。任何机器上只要缓存没跟上（首次运行、换机器、游戏目录被还原或被清理）→ 头一阵都要重编译，表现为「开机头一阵卡、玩一会才顺」。缓存随包带是解法。
6. **破解版专属**：游侠 2010 顿卡合集里 SKIDROW 版有人「关掉声音选项里的混音」后不卡（我们是 SKIDROW 版，可作旁证，优先级低）。

### 一律不采信（2026 攻略站的 AI 编造 / 有害偏方）
- 给 2010 年 DX9 游戏安「DX11 转换补丁」「DLSS / 光追 / 锐化」——引擎根本没有这些（PCGamingWiki：无 DLSS/FSR/光追）。
- 「结束 DWM 进程」「CPU 关联性只勾 0-3」「Win7 兼容模式 + 禁用全屏优化」——前者有害，后两者违反规则 18（不写系统/全局开关，交付要放到任何机器点一下就跑）。
- `cg_invalidCmdHintBlinkInterval 2048 / Duration 0`——2010 年论坛玄学，无机理、无复现，不进交付。

## 2026-11-10 追加：通关存档「打了还是从头开始」——真根因与配套落地（已验证）

- **用户现象**：把通关存档 `.svg` 放进 `players\save` 后仍从头开始；贴出的两行
  `sv_lastSave*` = `save\cuba.svg` 是**引擎每次退出都会重置的正常值**，不是病根。
- **真根因（社区 + 实机双证）**：本作关卡解锁进度在 `players\config.cfg` 的 `mis_01`
  （实机 `mis_01 = 0` = 一关没过 → 任务列表全黑条），**不在 .svg 里**。通关存档是两半：
  `save\*.svg` + 同目录 `config.cfg` 里的解锁标记，只拷一半等于没打。
  社区口径（2011 百度知道采纳答案 / 搜狗问问 / ZOL / 2017 网吧帖一致）：`seta mis_01 "0"` → `"30"`
  解锁全部关卡；等效游戏内做法是在主菜单挣脱椅子到 CIA 终端按 F 输 `3arc unlock`。
- **落地（启动器每次启动幂等修正）**：
  1. `ApplySaveUnlock`：`SaveUnlock=1` 时把 `mis_01` 写成 30（实测本版本有效，且引擎退出不重置它）；
  2. `FixSavePointers` 增加 `SaveFile` 优先：填了就固定把两行指向指定通关存档，
     **不再按 mtime 挑最新**（否则今天测试写的新检查点 `cuba-3.svg` 会把 2010 年的通关存档挤掉）；
     文件不存在自动退回按时间挑。本机配 `SaveFile=save\underwaterbase.svg`；
  3. `launcher.ini` 三个开关：`SaveAutoFix`（指针自动修）、`SaveUnlock`（关卡解锁）、`SaveFile`（指定存档）；
     不想全解锁/想自己管进度就 `SaveUnlock=0` 且 `SaveFile` 留空。
- **验证**：最坏初始态（`mis_01=0` + 两行回第一关）跑 `/display` → `mis_01 0→30`、

## 2026-11-10 追加：左栏文案换行（用户截图「左边这些字换行不对」）
- **现象**：`Treyarch` 被拆成 `Treyarc` / `h`，逗号、引号孤零零另起一行。
- **根因**：`DrawWrapped` 按像素宽度逐字符递减取字数，不认英文单词边界、不认中文标点禁则；
  `launcher.ini` 的 `Intro` 又是一行长句 + 写死 `\n`，超宽后二次折行正好切在词和标点中间。
- **修法（两处一起）**：
  1. 绘制层加 `TakeChars` 禁则：英文/数字单词不断在中间（退到最近空格后）、
     标点不做下一行行首（并到上一行）；`DrawWrapped` 与 `MeasureWrappedHeight` 共用，
     避免算高与绘制不一致。
  2. 文案层把 `Intro` 重排成短行（每行 ≤ 15 字，英文词独立成行），
     **源码默认 intro 同步成同一套**（原来还留着 CoD2 的文案，规则 14）。
- **证据**：`evidence\launcher-left-wrap-fixed.png`（窗口自身矩形取证）——
  `Treyarch` 完整、逗号引号不再孤行、段落整齐。中栏 ComboHint 是固定文案（规则 20），
  中文自然折行不属于断词，未改动。
