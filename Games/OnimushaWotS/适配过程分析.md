# 鬼武者：剑之道（Onimusha: Way of the Sword）适配过程分析

## 1. 背景与目标

游戏是 CAPCOM 的 RE Engine 作品，原生 DirectX 12，本机（RX 580 / 1920×1080）可直接运行，
不需要 DXVK、dgVoodoo 或 cnc-ddraw。本次适配只解决一件事：**分发给不同显示器的电脑时，
游戏必须至少按对方桌面分辨率输出，不能出现 240p 或分辨率被锁死。**

用户上一款分发的《生化危机 8》出现过：开发机配置正常，复制到部分电脑后输出 240p，
游戏内也改不回来。Onimusha 的接收方包含宽屏和 2K 显示器，因此不能沿用开发机的 `config.ini`。

## 2. 根因

RE Engine 的 `config.ini` 里有两组**机器相关**的显示键：

```ini
[Graphics]
DisplayType=Auto
FullScreenDisplayModeIndex=49
NormalWindowResolution=(1920,1080)
WindowMode=Borderless

[RenderConfig]
FullScreenDisplayMode=49
FullScreenMode=false
NormalWindowResolution=(1920.000000,1080.000000)
WindowMode=Borderless
```

`FullScreenDisplayModeIndex` / `FullScreenDisplayMode` 对应本机显示模式表里的序号，
`NormalWindowResolution` 是开发机的分辨率。把这份文件复制到另一台显示器：
序号可能不存在、分辨率可能小于对方桌面，游戏就会回退到 240p 或被锁在低分辨率。
**这类配置不能随包分发。**

### 2.1 现场反馈：网吧/PnP 装机可能检测不到显卡

用户此前分发《生化危机 8》时，开发机一切正常；后来在网吧客户的电脑上无意点开，发现游戏
GUI 只有一个小方块（240p 级别），游戏内也改不回来。用户推测：网吧电脑配置不低，但驱动是按
PnP 批量安装的，游戏可能识别不到显卡或驱动版本，于是回退到最低画质和最小分辨率。

这条无法在本机复现，但直接决定了本作的默认策略：**不能把画面完全交给游戏自动检测**。
默认项必须由启动器按当前物理桌面强制 `Borderless` + 桌面分辨率；“让游戏自动检测（重置）”
只作为可选的排障/重置项，并明确提示“检测不到显卡时可能回到最低画面”。
在 Borderless 下分辨率字段会被忽略，即使游戏检测失败写入低分辨率，输出仍按桌面铺满。

## 3. 本机实测

测试机：Windows 11 x64，AMD RX 580 2048SP，桌面 1920×1080，DPI 100%。

| 场景 | 配置 | 实测结果 | 证据 |
|---|---|---|---|
| 完全无 config.ini | 无 | 游戏自动生成 3616 字节配置，窗口/客户区 1920×1080 | `evidence/no-config-45s.png` |
| 无效索引 + 小分辨率 | `FullScreenDisplayModeIndex=999`、`NormalWindowResolution=(1280,720)`、`WindowMode=Borderless` | 窗口仍 1920×1080 | `evidence/bad-index-borderless-40s.png` |
| 最小显示配置 | 只写 `[Graphics]` / `[RenderConfig]` 的显示键 | 正常启动 1920×1080；游戏补齐后的配置与“完全无配置”逐字节一致（diff 无输出） | `evidence/config-minimal.ini`、`config-firstrun-auto.ini`、`config-expanded-from-minimal.ini` |
| 全屏配置 + 守卫 | `WindowMode=FullScreen`、`FullScreenMode=true`、`DisplayType=Test`、1280×720、索引 999 | 守卫改为 `Borderless`（两段）、`FullScreenMode=false`、`DisplayType=Auto`，只动显示键，画质键不变 | `evidence/config-fullscreen-test.ini` |
| 启动器 `/go` | 默认模式 | 游戏为 `game_starter.exe` 直接子进程，窗口 1920×1080，启动器陪跑，退出码原样回传 | `evidence/starter-go-visible.png` |
| 启动器 `/raw` | 直接启动 | 隔离目录内 `config.ini` 的 md5 前后完全一致，日志写“跳过所有画面预设” | `evidence/delivery-test.txt` |

**关键结论：Borderless 模式会忽略 `NormalWindowResolution` 和 `FullScreenDisplayModeIndex`，
实际输出充满当前桌面。**因此只要每次启动强制 `WindowMode=Borderless`，1080p、2K、宽屏
都会按各自桌面输出；不需要猜测对方的显示模式序号，也不需要用开发机的分辨率。

## 4. 实现

### 4.1 默认启动（桌面分辨率，推荐）

`game_starter.exe` 每次启动前：

1. `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，再用 `EnumDisplaySettings` 取物理桌面分辨率
   （失败退回 `Screen.PrimaryScreen.Bounds`）。
2. 如果 `config.ini` 不存在，写入只含显示键的最小配置（无画质键，不影响游戏的硬件检测）。
3. 如果存在，只改以下键，其他画质/按键/存档设置一律不动：
   - `[Graphics] WindowMode=Borderless`、`DisplayType=Auto`、`NormalWindowResolution=(W,H)`
   - `[RenderConfig] WindowMode=Borderless`、`FullScreenMode=false`、`NormalWindowResolution=(W.000000,H.000000)`
4. 第一次改动前把原 `config.ini` 备份到 `_legacy_compat_backup\OnimushaWotS\config.ini`。

“修复分辨率”按钮 / `/fixres`（兼容旧 `/fixdisplay`）使用同一套逻辑，
玩家分辨率异常时可手动执行。

### 4.2 直接启动（不改设置）

下拉框第 2 项“直接启动（不改设置）”，对应 `/raw /go`：完全跳过上面的显示守卫，
按游戏当前配置直接启动。用于排查“是不是启动器改配置导致的问题”，也是显示守卫的退路。

### 4.3 让游戏自动检测（重置画面设置）

下拉框第 3 项，对应 `/autodetect /go`（兼容 `/reset`）：先把现有 `config.ini`
备份到 `_legacy_compat_backup\OnimushaWotS\`，再写成 0 字节空文件，让游戏按当前电脑
重新检测硬件和画面。实测 0 字节配置会被游戏正常补齐（3616 字节）并按桌面启动；
适合配置被改坏、换显卡或换显示器后想彻底重来的情况。它不强制桌面分辨率，画面完全交给游戏；
默认项仍然是“桌面分辨率（推荐）”。

界面规范：中栏标题用“启动说明”，用文字解释每个启动选项，说明文字、下拉框、启动按钮
紧挨着排；不单独显示“画面 1920×1080”这类信息块，状态栏只写“已就绪”；
修复按钮统一叫“修复分辨率”。

### 4.4 控制台启动器

`game_starter.bat` 与 GUI 选项/顺序/默认值一致：

```
1  启动游戏（桌面分辨率，推荐）
2  直接启动（不改任何设置）
3  让游戏自动检测（重置画面设置）
4  修复分辨率（重置为桌面分辨率）
5  打开运行日志
6  退出
```

`/go` 跳过菜单按默认项启动；菜单项 2 调用 `game_starter.exe /raw /go`，
菜单项 3 调用 `game_starter.exe /autodetect /go`。
两者都满足平台托管契约：游戏是启动器的直接子进程、启动器陪跑到游戏退出、
退出码原样回传、玩家关启动器窗口不杀游戏（隐藏到托盘继续陪跑）。

## 5. 交付包

`Games\OnimushaWotS\release\`：

```
一键应用.bat        校验游戏目录，备份并删除目标机的 config.ini，再复制启动器
一键撤回.bat        按记录恢复被替换文件；目标机已重新生成 config.ini 时保留并提示
payload\            只含启动器文件，不含 config.ini
  game_starter.exe
  game_starter.bat
  game_starter.sha256
  launcher.ini
  _tools\nircmd\ircmdc.exe
  manifest.txt
```

**应用时删除 `config.ini` 是故意的**：让每台电脑首次启动时按自己的桌面和硬件重新生成，
不继承开发机的显示索引和画质预设。撤回时如果玩家已经进过游戏、`config.ini` 已重新生成，
脚本不会覆盖当前文件，只在记录里写明原配置备份位置。

## 7. 双视角自检（2026-11-03）

### 开发者视角

- 游戏/引擎提供什么：RE Engine 自动检测画质，游戏内「设置」提供画面、视角和操作页；
  启动器只能控制启动、显示兜底、日志和进程托管，不能控制画质档位、存档和网络。
- 每个选项对应真实行为：`游戏自动检测（推荐）` 不改 `config.ini`；`画面异常时（固定桌面分辨率）`
  在后台写 `Borderless + 当前桌面分辨率`；`修复分辨率` 走同一套显示兜底；日志/退出是实际动作。
- 操作说明来源：游戏内「操作」页实测键位（`evidence/controls-keyboard-window.png` 及
  `controls-keyboard-scroll1..5.png`）；核心提示“化劲/回避/不要贪刀”来自社区攻略，
  不自己编。参考：[GAMES.GG 战斗指南](https://games.gg/zh-CN/onimusha-way-of-the-sword/guides/onimusha-way-of-the-sword-%E6%94%BB%E7%95%A5%E5%85%A8boss%E6%89%93%E6%B3%95%E6%8C%87%E5%8D%97/)、
  [Xbox Wire 战斗指南](https://news.xbox.com/en-us/2026/09/03/onimusha-way-of-the-sword-tips-guide-combat/)、
  [电景风攻击手段一览](https://m.dianjingfeng.com/gl/94712.html)。

### 玩家视角

- 能看懂吗：默认「游戏自动检测（推荐）」；第二项写明「画面异常时」，知道什么时候用；
  「修复分辨率」写明修复对象；「锁定目标」替代生僻的「注视」；核心提示解释化劲时机。
- 下一步：点「启动游戏」；画面不对选第二项或点「修复分辨率」；出错点「打开运行日志」。
- 右栏覆盖角色动作 + 菜单；没有“自动存档”“加载慢”“分辨率参数”等平台已负责或重复的话。
- 缺什么：未列全部次要操作（奔跑 Shift、鬼之武器 G、鬼灯袋 E 等），只保留核心；
  玩家可在游戏内「操作」页查看完整键位。首次加载提示按用户要求不写。

自检结果：通过。若后续加内容，必须再回答“来源是什么、玩家能不能看懂、缺什么”。

## 8. 未验证

- 2K（2560×1440）、超宽屏（3440×1440）、150% DPI 的真机测试。
  机制上：启动器按物理桌面写配置，Borderless 充满桌面；本机只实测了 1920×1080。
- 不同显卡/驱动下 RE Engine 的自动画质档位（本机 RX 580 自动生成 PCLowest，可进游戏内调整）。
- 游戏正常菜单退出的干净退出码（自动化双击“结束游戏”触发过游戏自身 `0xC0000005`；
  启动器回传无误，但未单独复测一次纯菜单正常退出）。

## 9. 风格定案与图标入库（2026-11-03 第二轮）

- 先按用户要求把 GUI 做成**玻璃拟态**（紫青渐变 + 半透明卡片 + 白色渐变主按钮），
  证据：`evidence\launcher-glass-trial.png`、`evidence\launcher-glass-menu-trial.png`。
  落地时发现 Framework 的 `System.Drawing.Drawing2D.Blend` 在这套工具链上没有颜色数组成员，
  多段渐变改用 `PathGradientBrush` 的中心/四周色实现辉光（记进技能，别再撞一次）。
- 用户看完定案：**以后统一按拟物皮革做**。已回滚成皮革主题并保留全部功能改动
  （两项下拉、显示守卫、双缓冲自绘下拉、页脚烫金 `YunGame`）。
  证据：`evidence\launcher-leather-final.png`（默认态）、`launcher-leather-menu.png`（展开菜单）、
  `launcher-leather-mode2.png`（鼠标切到第二项）、`launcher-leather-kbd-mode2.png` +
  `launcher-leather-focus-zoom.png`（Tab 焦点环 + `↑↓` 换项）。
- **图标入库**：`D:\ico.ico` 复制为仓库资源 `assets\ico.ico`
  （SHA-256 `4fb1af642a2e8c608ee47d91caa0b238012aee9a51d31bb1ffd30196d086c495`）；
  `build.ps1` 改成 `-win32icon:<仓库>\assets\ico.ico`，运行时删掉 `D:\ico.ico` 兜底
  （交付机上没这个路径），取不到只用系统默认图标并写日志。
- **补的键盘缺口**：自绘下拉框 `Panel` 原本进不了 Tab 链。现在焦点序号 4 = 下拉框，

  `nircmdc.exe` 并同步 manifest。**其余游戏（CS16 / FiveStar / Heroes3 / FutureSoldier /
  DFBHD / Prototype1 / Prototype2 / TheSaboteur）的 build 脚本还是老名字，尚未一起改。**
- 左栏介绍文案改成整段（不再手工断行）：`DrawWrapped` 会按列宽自动折行，
  手工断行 + 自动折行叠加会出现「战国题材」「太刀」这类孤字行。
- 本轮构建：`game_starter.exe` 45 KB（红线 60 KB），
  SHA-256 `147b8d48c1b03cf56833a78ff033656fa498f1bd976e54e5a29440e46f6578a8`；
  `tools\modes-test.ps1` 7 项全 PASS（默认不动 `config.ini`；`/desktop` 写 Borderless + 桌面分辨率 +
