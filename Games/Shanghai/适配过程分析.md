# 血战上海滩 适配过程分析

游戏：血战上海滩（抗日：血战上海滩，南京祖龙 2003，Angelica 引擎，D3D8）
游戏目录：`D:\YunGame\IndieGame\shanghai`
工作区：`Games\Shanghai\`（源码 src、工具 tools、证据 evidence、备份 backup、构建 build.ps1）
交付：`Games\Shanghai\release\`（payload 6 文件 + 一键应用.bat + 一键撤回.bat + 交付记录.txt）
日期：2026-11-15

## 一、社区调研结论（先查再做，按用户要求）

- 社区成熟方案一致且与现场文件互相印证：**`-windows` 参数 + （可选）桌面降 800×600**；
  游戏目录自带的 `说明(必看).txt` 写的就是这套（快捷方式加 `-windows`，游戏内设 1024×768），
  另有 `~` 控制台秘籍（god_on / haveallweapon / addammo / ammonolimit）。
- **没有任何一篇是针对本游戏实测过 DXVK / dgVoodoo2 的**，搜到的都是泛泛通用教程。
- 结论：社区方案解决「能不能跑」，不解决「新系统上画面小」；兼容层这条路自己实测。

## 二、本地诊断（探针与取证）

- 主程序 `shanghai.exe` 32 位、D3D8（`Direct3DCreate8` / Angelica 引擎）。
- 本机 D3D9 探针 32/64 位全通；补写 D3D8 探针（`Games\Shanghai\tools\D3D8Probe.cs`）实测三条路：
  原生 `SYSTEM32\d3d8.dll`、DXVK 2.5.3（Vulkan）、dgVoodoo2 —— 建设备全部 OK。
- 游戏 `Logs\A3D.log` 实锤：引擎固定 `Create device 800x600x16`。
- **不带 `-windows` 直接崩**：`A3DDevice::Init(), Can not change display mode!`（引擎自己切显示模式，
  Win11 切不动）——`-windows` 是绕不过去的，启动器固定带。
- 桌面 1920×1080@60 不动、`-windows` 直接跑：能进游戏，窗口 800×600 缩在左上角。
- `ini\options.ini` 是引擎**加密格式**（无法按任何常见编码解码），游戏内画面设置存这里，启动器不碰。

## 四、兼容层 conf 之谜（重要教训，如实记录）

多轮实验证明：**这批 `tools\dgvoodoo\x86` 的 DLL 不读 `dgVoodoo.conf`**：

- `Resolution` 四种格式（`1024x768` / `h:,v:,refrate:` / Glide 段 / DirectX 段）、
  `AppControlledScreenMode` 两种值、水印开关、五件套（加 DDraw.dll/D3DImm.dll）全试过，
  窗口恒 800×600；
- **正面破坏性测试**：`OutputAPI = d3d12_fl11_0`（机器上无该输出组件，conf 若被读必挂），
  游戏照跑 → conf 被 100% 无视；
- 原版 conf、CPL `-writedefaultconfig` 生成的 conf（与仓库 conf 逐字节一致）均无效；
- 进程模块实测：游戏加载的是游戏目录 `d3d8.dll`，输出走系统 D3D11/DXGI（dgVoodoo 2.8x 行为），
  层在工作（翻译正常、水印可见），但**水印恒开**（水印默认值即开，conf 关不掉）；
- 这批 DLL（D3D8/D3D9/D3DImm/DDraw）**不含 dgVoodoo 字符串、无版本资源**（仅 CPL 和 conf 有），
  来源存疑。仓库级问题，等点名再排查其他游戏。

工程决策：铺满效果由**启动器切桌面**实现（不依赖 conf）；conf 随包保留（换层版本时是必需格式）；
启动器源码注释里写死这条教训，禁止后人依赖 conf 做布局判断。

## 六、实测验证记录（最终 exe）

- `--go` 默认档：1920×1080 → 切 800×600（日志「启动前设显示模式 800×600@60：成功」）→

- `--go --mode=2` 备用档：桌面全程 1920×1080 不动，游戏窗口模式跑起来。

  已兼容三种前缀；备用档日志重复打两遍现场读数，已去重。
- 崩溃取证：强杀不算崩溃，WER 无记录（日志如实写「没抓到」）；真实崩溃走 `Crash.Capture`。

## 八、一键秘籍（2026-11-15 第二轮追加）

- 用户拍板把社区文章（CSDN agent.csdn.net/6a4f298a662f9a54cb8cb05a）的一键秘籍做进启动器。
- 实现：`src\Cheats.cs`（SendInput + KEYEVENTF_SCANCODE 扫描码，Angelica 引擎读 DirectInput，
  VK 事件部分键不认）；`god_on/god_off/haveallweapon/addammo/ammonolimit` + 「一键全开」三连。
- 交互：中栏六按钮（游戏运行中点击 → SetForegroundWindow 游戏窗口 → ~ 开控制台 → 扫描码逐键
  输入（每键 60-80ms，打太快丢字符）→ 回车 → ~ 关）。游戏没跑只提示不报错。
- 自证通道：`/cheat=名`（三前缀兼容）控制台直发、退出码 0/3；`--go --cheat=名` 游戏窗口就绪后自动发。
- 实测：`/cheat=all` 退出码 0，游戏内可见生效（角色手持发光新武器=haveallweapon，弹药 ∞），
  取证 evidence\cheat-before.png / cheat-after.png。
- **两个坑**：
  ① `scripts\capture-window.ps1` 默认截完杀进程（-KeepOpen 才保留）——游戏"-1 退出"假象两次误导排查；
  ② 对本引擎发 WM_CLOSE 它不响应也不退出（假死：画面停、声音继续）——测试收尾一律 Stop-Process 强杀，
     玩家正常退出走游戏内菜单不受影响。

## 九、游戏内分辨率重置（2026-11-15 用户实测反馈）

- 现象：默认档桌面 800×600 下游戏菜单显示不全——用户游戏内把分辨率设成了 1024×768，
  存在 `ini\options.ini`（引擎加密格式，无法定向改）。
- 处理：备份（backup\options.ini.1024x768.user）后移走该文件 → 引擎按内置默认 **800×600** 重建
  （实测窗口 800×600 @ (0,0)，evidence\reset-options.png）。
- 结论：无 options.ini = 800×600 默认；玩家正常退出后引擎自动写回当前设置。
  提醒玩家：游戏内不要把分辨率调到 1024×768（会超出默认档的 800×600 桌面）。

## 十一、去层定案 + 三重桌面还原保障（2026-11-15 用户第三轮拍板）

- 用户实机反馈：挂层后游戏仍卡死（画面停、声音在），且目标玩家是不懂电脑的老年人——
  「结束任务都结束不了，还要自己手动恢复桌面分辨率，直接就是灾难」。
- **定案：兼容层整个移除**。走系统原生 D3D8（探针实测通，游戏首启 A3D.log 也是原生建设备）；
  游戏目录/payload/manifest/交付记录全清层；启动器启动时幂等清理旧版残留层文件（StaleLayerFiles）。
- **三重桌面还原保障**（老年玩家绝不需要手动恢复分辨率）：
  ① 主启动器 try/finally（原有）；
  ② 独立恢复进程 `--restore=w,h,rate,pid`：切桌面前 SpawnRestorer 拉起，等游戏 pid 退出后
     Env.RestoreByMode 还原再自杀（演练：强杀主启动器+杀游戏 → 桌面还原 1920×1080@59 成功）；
  ③ 看门狗加 IsHungAppWindow 检测：窗口未响应连续 60s → WM_CLOSE → 10s 不退强杀（「画面卡住
     声音在」型卡死，原看门狗只查「窗口消失」型查不出这种）。
- **演练抓到的灾难级 bug**：恢复参数初版存了目标模式 800×600（会把桌面钉死在游戏分辨率），
  已修为存 Apply 返回的 before（原桌面 w/h/实测刷新率，本机 59Hz——刷新率必须原样传）。
- 残余风险（如实记档）：恢复进程与主启动器同名（交付铁律只做 game_starter.exe），玩家在任务
  管理器按名字全杀 game_starter 会连带杀掉恢复进程；按「应用」列表杀则只杀有窗口的，无碍。
- 自救验证：`--restore=1920,1080,59,0`（pid=0 不等待立即还原）曾把演练中钉死的桌面救回——
  这也是远程排障的手动恢复口。

## 十二、界面规矩 + 崩溃真相 + 自愈（2026-11-15 用户多轮拍板收口）

- **界面规矩（用户三条消息定案）**：不藏托盘（老年玩家找不到托盘图标）；窗口最小化=正常的
  任务栏最小化（点任务栏图标随时回来）；关闭就关闭——游戏运行中关窗=同时收走游戏进程，
  不留任何后台（GoToTray/NotifyIcon/陪跑机制已整体删除）。
- **崩溃真相**：裸原生 D3D8 并非必崩——4s 0xC0000005（ntdll +0x934d9）两次都发生在
  「层刚移除→引擎弹『设置最优设置？』→启动器自动点掉」之后；指纹写回后连续三轮 25s+ 稳定。
- **启动即崩自愈**：RunGame 返回 0xC0000005 且 <15s → 自动重拉一次（桌面还停在 800×600 不再切）；
  重拉前收走上一条恢复进程（restorerPid），否则它会抢着把桌面还原掉。客户机升级场景
  （旧层指纹）靠这道自愈兜底。
- **僵尸 shanghai.exe 实锤**：ThreadCount=0、20K 内存、taskkill 拒绝访问——卡死游戏留下的
  系统级残留，只能重启清掉；在场不影响新游戏运行（实测多轮）。启动器对它们无能为力也不需要管。
- **DXVK 实验插曲**：DXVK 三件套放入游戏目录后没被加载（且被 CleanupStaleLayers 当残留删了）；
  原生稳定后 DXVK 不再需要，只留实验记录。
- 自救通道：`--restore=w,h,rate,0`（pid=0 立即还原）可手动把桌面拉回（实测把演练中钉死的
  800×600 桌面救回 1920×1080）。
