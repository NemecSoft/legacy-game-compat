## 2. SG8Launcher.exe 是什么

- PE32+ 原生 x64 GUI，`.text` 6.7 MB + `.rsrc` 1.9 MB，**尾部 125 MB overlay**；
- overlay 里有 529 个 `BSJB`（.NET 元数据）与整套 WPF 运行时（`PresentationCore/Framework`、
  `wpfgfx_cor3.dll` 等），运行时会把原生部分解到 `%TEMP%\.net\SG8Launcher\<随机>\`；
- 也就是说：**它是 .NET（WPF）单文件包，程序名 `SG8OfflineLauncher`**（overlay 末尾能看到
  `SG8OfflineLauncher.deps.json` / `.dll` / `.pdb` 文件名）；
- 尾部不是标准 .NET 单文件格式（结尾是文件名字符串而不是 hash+magic+长度），程序集不能直接抽出来反编译。
  所以实现细节**改用运行时取证**确定（见下），没有靠猜。
- UIA（UI Automation）可以完整读到它的控件树：19 个元素，两个 `Hyperlink`（`萌芽游戏`、`XDGAME`）
  和三个 `Button`（`日志目录`、`停止游戏`、`启动游戏`），按钮都暴露 `InvokePattern`。
  取证脚本 `tools\uia-probe.ps1`。

界面（`evidence\original-01-main.png`、`original-02-running.png`）：
标题「三国群英传 8 离线启动器」，状态行 + 进度条，运行日志框（本次会话 / 最新日志），
左下角两个推广链接，右下角「停止游戏 / 启动游戏」。它**没有任何游戏选项**（没有分辨率、语言之类），
也不会自动开始——实测打开后静置 100s 不产生会话，必须点「启动游戏」。

## 4. 为什么不能复刻这套机制（实测，不是推测）

| 试法 | 结果 |
|---|---|
| 直接 `GAME\SG8.exe`（无环境、无便携 Steam） | 约 6s 崩，退出码 `0xC0000005`；还会留下两个**挂起**的子进程（`tools\direct-test.ps1`） |
| 带全套 `STEAM*` / `SG8_*` 环境变量 + 先起 `Runtime\steam\steam.exe -silent`，但不注入 | 同样 `0xC0000005`（`tools\env-launch-test.ps1`） |

结论：离线环境靠的是**注入 + challenge 口令 + 私有注册表视图 + 反调试标记**这套包内自带的受保护实现。
复刻它等于重写一遍绕过机制，既不该做也不稳（口令/标记一变就废）。
所以我们的启动器**不复刻离线机制**，只负责「玩家-facing 的启动器职责」，离线部分调用包内自带的 `SG8Launcher.exe`。

## 5. 我们的实现（`Games\KingdomHeroes8\src\Launcher.cs` → `game_starter.exe`，21 KB）

C# / .NET Framework 4 WinForms + UIAutomation（`UIAutomationClient/Types`、`WindowsBase` 是框架自带，不是第三方）。
流程：

1. 读 `launcher.ini`（`OfflineLauncher` / `GameName` / `StartButtonText` / `CoverPad`）；
2. 拉起 `SG8Launcher.exe`；
3. **按主窗口句柄**在 UIA 里挑窗口——同一 pid 有多个顶层窗口，挑错会拿到空控件树（既找不到链接也点不到按钮）；
4. 它会记住上次窗口位置，被挪到屏幕外时 WPF 不再排布局、UIA 树是空的，所以先把窗口拉回屏幕内；
   （实测：窗口在 `-32000` 时 `FindAll(Descendants)` 返回 0 个元素，`tools\offscreen-invoke-test.ps1`）
5. 遮罩：取窗口下半部、靠左 45% 以内的所有 `Hyperlink`，合并矩形 + `CoverPad`，
   用 `PrintWindow`（`PW_RENDERFULLCONTENT`）抓原版窗口**自己**的画面取页脚底色
   （直接截屏会采样到压在上面的别的窗口，实测取到过绿色按钮色 `22,113,90`），
   贴一个无边框、`WS_EX_NOACTIVATE|WS_EX_TOOLWINDOW`、不抢焦点的从属窗口（`GWLP_HWNDPARENT`）；
   从属窗口只跟层级不跟位置，所以每 400–500ms 重新算一次矩形跟着贴（拖动、最大化、UIA 迟到都能跟上）；
6. 自动点「启动游戏」：找 `Button` 且子文本含配置里的按钮名、`IsEnabled` 且有 `InvokePattern` 才点。
   **原版要先跑完依赖检查**，点早了它不响应，所以带重试（每 12s 一次，最多 6 次）；
   另外窗口刚出现约 800ms 时 WPF 还没排布局，控件树是空的（实测会打出「控件树一个元素都没有」），
   所以每轮发现树为空就重新抓窗口 + 重新拉位置，而不是放弃；
7. 认游戏进程：游戏进程被加了保护，读 `StartTime` 会拒绝访问，因此**按父进程链**认
   （`SG8Launcher → steam.exe → SG8.exe`），顺带避开上一轮遗留的挂起进程；
8. 陪跑等退出：**绝对不能对游戏进程用 `Process.EnableRaisingEvents = true`**——
   实测开着运行中的游戏挂上事件后 5 秒内它就自杀（保护检测），
   改成自己 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE)` + `GetExitCodeProcess` 轮询取退出码，
   游戏就能正常活到玩家关它；
9. 收尾：给原版窗口发 `WM_CLOSE` 让它自己清理（删临时注册表、停便携 Steam），12s 没退再结束它；
10. 技术细节全进 `运行日志.txt`，界面上不出现注入/管道/注册表这些词。

命令行：`/go`（默认，自动点）、`/noclick`（只搭环境，玩家自己点）、`/nopatch`（不遮推广，排障用）。

`game_starter.bat` 是同选项的控制台版：1 启动游戏 / 2 启动游戏（自己点）/ 3 打开运行日志 / 4 退出，
`/go` 走默认项；由 bat 调 `game_starter.exe`，游戏退出码原样回传。

**与标准形态的偏差（有意为之，用户定案）**：这个包没有做我们那套三栏皮革 GUI，
因为玩家要看的状态/日志原版界面已经给了，用户明确要求「只把左下角的 XDGAME / 萌芽游戏 隐藏掉就行了」。
所以本启动器没有自绘界面，也就没有 YunGame 页脚与品牌自校验；仍然保留统一命名、统一图标、
`game_starter.sha256`、绿色交付与一键撤回。

## 7. 存档目录名 `76561198747544758` 是从哪来的

`%LOCALAPPDATA%\UserJoy\SG8\Save(Test)\76561198747544758`（以及 `GlobalSave(Test)\` 同名目录）
里的这个数字**不是 Windows 用户名、也不是本机 Steam 账号**，而是一个 **SteamID64（CSteamID）**，
由包内 `Runtime\MiniPipeDll.dll` **写死**返回：

- 游戏调 `ISteamUser::GetSteamID`（iface=1，msg=`0xD6FC3200`），MiniPipe 应答
  `GetSteamID -> 011000012EECECB6`（`Runtime\logs\minipipe.log`，13:40 与 13:48 两轮会话都是同一个值）；
- 这 8 字节就是 `MiniPipeDll.dll` **文件偏移 153104** 的常量（小端 `B6 EC EC 2E 01 00 10 01`），
  紧挨着它的是 `0x7A69=31337`（就是日志里的 `serial=31337`）、`0x000D5ACA=875210`（appid）和字符串 `D:\Steam`
  ——一张写死的「假账号 + 假安装路径」表；
- 拆开：universe=1(Public)、type=1(Individual)、instance=1、**accountID=0x2EECECB6=787279030**，
  即 `76561197960265728 + 787279030 = 76561198747544758`，与目录名逐位一致；
- 所以**换任何机器跑这个包，存档文件夹名都一样**（常量在 DLL 里），文件夹可整体搬走；
  本机也没有真 Steam（`Program Files (x86)\Steam` 不存在），排除了「从本机登录历史取号」。

容易混淆的另一个数：启动器给游戏进程设的环境变量 `STEAMID=76561198747582902`（accountID 787317174）**不是**目录名来源。
它在本机两轮会话里不变，但在包内任何文件里都搜不到（十进制文本、8 字节小端、低 4 字节都没有），
只在崩溃转储里作为环境块出现过 → 是 `SG8Launcher.exe` 运行时算出来写进环境块的，
游戏建存档目录时用的是 SteamAPI 的应答（上面那个常量），不是这个环境变量。

## 8. 已知限制 / 未验证

- **游戏内的画面设置不持久**：原版启动器给游戏装了临时注册表视图（`HKCU\Software\SG8Offline\Transient\Game_<pid>_<guid>`），
  游戏写进去的分辨率/窗口模式在退出时随视图一起删除（实测退出后 `HKCU\Software\UserJoy` 不存在）。
  这是原版行为，我们没有改动它，也没法在不复刻那套注入机制的前提下修好它。
- **我们无法给游戏传命令行**（`-force-d3d9` / `-screen-fullscreen` 之类）：游戏进程是原版启动器创建的，
  我们只能等它出现。因此没有「画面异常时（固定桌面分辨率）」这种选项，也不写注册表去冒充它。
  本机原生 DX11 实测正常；换机器若 DX11 起不来，备选是改 `GAME\SG8_Data\boot.config`
  或让玩家在原版启动器之外自行处理，**未实测**。
- 遮罩依赖 UIA 能读到控件树：若原版窗口被最小化或挪到屏幕外，UIA 树为空，遮罩会退回固定条带
  （窗口左下 16..300 × 底部 40px），仍然盖住链接但边缘可能留白。
- 150% / 200% DPI 缩放与 2K/超宽屏未实测（本机 1920×1080 @100%）。
- 长时间游玩、正式存档/读档、成就与云存档、手柄全键未验收。
- 上一轮崩溃留下的两个**挂起**的 `SG8.exe`（pid 15992 / 18652）本机 `taskkill` 报「拒绝访问」，
  需要管理员权限或注销/重启才能清掉；我们的启动器按父进程链认进程，不会被它们误导。

## 9. 双视角自检（AGENTS 规则 23）

开发者视角：
- 每条结论都有出处：机制来自它自己的 `wpf-launcher.log`、进程树、环境块、注册表快照；
  「不能复刻」的两条是实测退出码，不是推测。
- 只做我们控制得了的事：拉起、遮罩、点按钮、陪跑、回传退出码；不承诺画质、帧数、存档、云功能。
- 不碰不属于我们的东西：`SG8Launcher.exe`、`GAME\`、`Runtime\`、存档目录一律只读，指纹留档。

玩家视角：
- 双击 `game_starter.exe` 就进游戏，看不到推广链接；状态和日志还在原来的窗口里，看得懂。
- 界面里没有出现注入 / 管道 / 注册表 / UIA 这些词，技术细节都在 `运行日志.txt`。
- 缺什么：没有我们的三栏介绍界面（按用户要求保持原版界面）；
  「游戏内改了分辨率下次又变回来」这条还没用玩家能懂的话写进界面提示，待用户确认要不要加。
