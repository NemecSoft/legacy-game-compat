# 正当防卫 Just Cause 1 —— 适配过程分析

- 游戏目录：`D:\YunGame\Z\JustCause1`（硬盘版，Steam 补丁 81984，2006 Eidos/Avalanche）
- 汉化：梅毛补丁（简体中文）—— `Archives\pc3.arc` / `pc4.arc` / `pc.tab` 被替换，
  新增 `dinput8.dll`（ASI Loader）+ `scripts\*.asi` 一堆功能补丁
- 本机：Win11 x64 / AMD RX 580（原生 D3D9 全挂）/ 无硬件 OpenGL
- 结论：**DXVK 2.5.3 + 裁剪版 JCSubtitleOverlay（只保留 UTF-8 解码补丁）= 中文正常、可玩**

## 1. 症状

用户反馈：进游戏后所有汉字都是方块（`□□□□`），过一会儿闪退。

复现（两次运行都稳定复现）：

- 启动器 / 直接双击 `JustCause.exe`，约 5–10 秒进程退出，退出码 `0xC000001D`（非法指令）；
- 闪退前的画面：菜单和 HUD 全是方块，例如 `★ □□□□□□□□□□□: □`；
- 原生启动（无 DXVK）还会额外弹 DirectX 顶点着色器错误（本机原生 D3D9 不可用）。

## 2. 探针（先量再猜）

| 项 | 结果 |
|---|---|
| `D3D9Probe32.exe` 裸跑 | adapter0 `0x8876086A`（D3DERR_NOTAVAILABLE），全屏/窗口全挂 → **原生 D3D9 不通** |

| `JustCause_d3d9.log` | DXVK 初始化正常：`VK_FORMAT_R8G8B8A8_UNORM`、`1920x1080`、`VK_PRESENT_MODE_IMMEDIATE_KHR` |
| 文件导入 | `JustCause.exe` 导入 `d3d9.dll`、`dinput8.dll`；`d3dx9_26.dll` 是游戏自带的 |

→ 图形层选 DXVK 2.5.3（与 Road Rash / DFBHD 同一份 x86 `d3d9.dll`）。

## 3. 方块字的根因：汉化补丁依赖一个「解码补丁 ASI」

汉化文本已经在游戏资源里（替换的 `pc3.arc`/`pc4.arc` 里有中文字库和文本），
但游戏 exe 里的 3 字节 UTF-8 解码器会把 `E4 B8 AD` 这类汉字解成 **U+E000 区（私用区）**：

```
14A727C  33 D2             xor  edx,edx
         8A 51 01          mov  dl,[ecx+1]        ; b2
         0F BE 49 02       movsx ecx,[ecx+2]      ; b3
         0F BE C0          movsx eax,al           ; b1
         83 E2 3F          and  edx,0x3F
         25 00 F0 00 00    and  eax,0x0000F000     ; ← b1&0xF0 恒为 0xE0 → 永远是 0xE000
         C1 E2 06          shl  edx,6
         03 D0             add  edx,eax
```

即：原版把三字节序列固定映射到 `0xE000+`，而汉化字库里没有私用区字形 → **方块**。

`JCSubtitleOverlay.asi` 的伪代码（Ghidra 12 反编译 `Games\JustCause\tools\DumpRefs.java` / `DecompAt.java`）：

```
DllMain → CreateThread(sub_10003470)
sub_10003470:
  1) MH_Initialize
  2) LoadLibrary("d3d9.dll") → Direct3DCreate9(0x20) → 把 vtable+0x40（CreateDevice）
     换成自己的 hook → Release        （用来在设备创建后装 Present/EndScene + D3DX 字幕）
  3) 在主模块内存里扫 25 字节特征码，唯一命中 → VirtualProtect 改 25 字节
     33 D2 8A 51 01 0F BE 49 02 0F BE C0 83 E2 3F 25 00 F0 00 00 C1 E2 06 03 D0
     33 D2 8A 51 01 0F BE 49 02 0F B6 C0 83 E2 3F 24 0F C1 E0 0C C1 E2 06 03 D0
     （and eax,0xF000 → movzx eax,al; and al,0x0F; shl eax,0x0C，得到真正的码点）
  4) MH_CreateHook(match-0x51, sub_10003B20)   ← 崩在这里
```

**两个 bug（本 exe 版本上必现）**：

1. `match-0x51` 算出来是 `0x14A722B`，正好落在 `0x14A7226` 那条 6 字节 `jns` 的**立即数第 4 个字节**上
   （不是指令边界）。MinHook 从半个指令开始拆指令、建跳板，游戏一跑到文本解码就 `0xC000001D`。
2. 就算钩子地址对了，它也是给「自绘字幕层」用的；解码补丁本身已经让游戏原生字幕/菜单/HUD
   全部显示中文，这一层不再需要。

## 4. 修复：从原版 ASI 裁出 `JCTextFix.asi`

`Games\JustCause\src\build-textfix.py` 从原版 ASI 上打两处补丁（都是 5 字节、都不在 PE 重定位项上）：

| 位置（RVA，基址 0x10000000） | 原字节 | 新字节 | 作用 |
|---|---|---|---|
| `0x349B` | `85 C0 74 19 B9` | `E9 B4 00 00 00` | 跳过整个 D3D9 vtable hook 块，直接进解码补丁 |
| `0x3809` | `E8 F2 E8 FF FF`（call MH_CreateHook） | `B8 01 00 00 00`（mov eax,1） | 让 CreateHook 返回错误码，跳过 0x14A722B 这个非法钩子 |

> 踩过的坑：第一版把跳转写在 `0x34B8`（`push "d3d9.dll"`），那 5 个字节的立即数里有
> `IMAGE_REL_BASED_HIGHLOW` 重定位项（RVA 0x34B9）。ASI 被加载到非首选基址时，loader 会把
> 重定位增量加到 rel32 上，跳转直接飞掉 → 启动即 `0xC0000005`。换到 `0x349B`（无重定位）后正常。

落地形态：

```
scripts\JCTextFix.asi      生效（= 原版 ASI 裁掉两个 hook，只留 25 字节解码补丁）
_backup\JCSubtitleOverlay.asi  原版 ASI（恢复原版用）
_backup\JCTextFix.asi      重装用
```

## 4.5 注册表：`reg.fix.exe` 的真实写入项

- `reg.fix.exe`（268,307 字节，sha256 `150f5728…`）是 **UPX + AutoIt3** 编译；REA/Ghidra 12.1.3
  打开为 `UPX0/UPX1`，解包后 585,747 字节；`strings` 只看到 AutoIt 运行时，
  用 AutoIt-Ripper 1.2.0 提取出脚本 `analysis/ripped/script.au3`（687 字节）。
- 脚本写入（32 位视图，即 `WOW6432Node`）：
  - `HKLM\SOFTWARE\Eidos\Just Cause`（建项）
  - `Language` = `REG_DWORD 0x00000409`（1033）
  - `InstallPath` = `REG_SZ @ScriptDir`（游戏目录，无尾反斜杠）
  - `HKLM\SOFTWARE\Eidos\Just Cause\1.00.0000`（建项）
- 脚本头 `#AutoItWrapper_UseX64=n`，reg.fix.exe 是 32 位；游戏也是 32 位，必须用
  `/reg:32` / `RegistryView.Registry32`，不能写 64 位视图。
- 交付实现：
  - `game_starter.exe` 启动前 `EnsureRegistry()`：已正确就不写；缺失才写；无权限时用自身
    `/fixreg` 走 UAC 再写一次。
  - `修复注册表.bat`：独立写四项，带管理员请求和“已就绪”检查；`game_starter.bat` 启动前
    调用 `game_starter.exe /fixreg`，`兼容修复.bat` 也调用。
- 实测：先导出原项到 `evidence/JustCause-registry-before.reg`，删除 32 位项后分别运行
  `game_starter.exe /fixreg`、`修复注册表.bat /quiet` 和 `game_starter.exe /go`（GUI 自动路径），
  三者都重建成功：`Language=1033(DWord)`、`InstallPath=D:\YunGame\Z\JustCause1`、`1.00.0000` 存在。
  本机原本已有该项（reg.fix.exe 之前跑过），恢复后值一致。
- 未验证：非管理员会话的 UAC 弹窗/取消路径（本机以管理员会话测试；代码走 `/fixreg` 提权）。

## 4.6 平台启动：保留 GUI 选择

- 2026-11-02 D003 报告 `game_starter.exe` 运行 84 秒后退出（`0xCFFFFFFF`）。主程序/内存都指向
  启动器，不是游戏本体；具体是游戏退出还是平台结束，需要看 `运行日志.txt`。
- **启动器不自动跳过菜单**：平台要保留显示方式/按键等选择时，直接无参数启动 `game_starter.exe`；
  只有零交互才传 `/go`。日志记录参数、父进程和是否 `/go`。
- Playnite 用「文件」启动动作，不要用 PowerShell 脚本/隐藏 `Start-Process`
  （火绒会拦“隐藏执行 PowerShell”）；如果平台仍把空闲 GUI 判成异常，应调整平台超时，
  而不是让启动器自动开游戏。

## 8. 复现修复步骤

1. `cd Games\JustCause && pwsh -File build.ps1`
2. 游戏目录双击 `兼容修复.bat`（会自检并补层、写注册表）；也可单独双击 `修复注册表.bat`
3. `game_starter.exe` → 启动游戏（启动前自动写注册表）；默认「显示帧数」写入 `dxvk.hud = fps`，要纯净画面可切「正常游玩」
